## ถ้าโยนนิยายเรื่องยาวให้ AI ไปเฉย ๆ

**❌ ไม่มี vibelore**

- ราวตอนที่ 10 คำเรียกขานเปลี่ยน ตัวละครที่ตายไปแล้วกลับมาพูด และกฎของพลังเปลี่ยนไปเงียบ ๆ
- ทั้ง AI และตัวคุณเองลืมปมที่วางไว้ในตอนที่ 3
- พอเซสชันหลุด ก็ต้องเริ่มจากการแปะ "เรื่องย่อที่ผ่านมา" ใหม่
- จะทำเป็นเว็บตูนก็ต้องอธิบายการจัดช่อง รูปลักษณ์ตัวละคร และตำแหน่งบทพูดใหม่ตั้งแต่ต้นทุกครั้ง

**✅ เมื่อมี vibelore**

- โลก ตัวละคร และเนื้อเรื่องถูกเก็บเป็นต้นฉบับหลักในรูปแบบ Markdown และร่างของทุกตอนจะถูกเทียบกับต้นฉบับหลักนั้น: **การละเมิดแบบ hard จะถูกแก้ ส่วนแบบ soft จะถามคุณก่อน**
- วางแผนตามลำดับ ทั้งเรื่อง → อาร์ก → ตอน และมีเพียงสิ่งที่คุณอนุมัติเท่านั้นที่กลายเป็นข้อจำกัดของตอนถัดไป
- งานที่ค้างจะทำต่อจากจุดเดิม คอมมิตเฉพาะต้นฉบับที่ผ่านการตรวจ และย้อนกลับได้ทีละตอน
- ภาษาของงานเขียนกำหนดด้วยอาร์กิวเมนต์ `language` เพียงตัวเดียว และภาษาอื่นนอกจากภาษาเกาหลีก็ใช้ขั้นตอนเดียวกัน
- มาพร้อมขั้นตอนการผลิตเว็บตูนที่ดึงตัวละครและสถานะจากต้นฉบับมาดัดแปลงตามเดิม กำหนดช่วงของต้นฉบับ ลายเส้น ภาพอ้างอิง จำนวนช่อง และโมเดลภาพ แล้วสร้างแต่ละฉากเป็นภาพเดียวรวมบทพูด

## เดโม 30 วินาที

แค่พูดแบบนี้ในช่องแชตของโฮสต์

> เขียนตอนถัดไปให้หน่อย เขียนเสร็จแล้วให้ดู ถ้าฉันอนุมัติก็ยืนยันเลย

```text
สัมภาษณ์ ─▶ ออกแบบงานเขียน ─▶ แผนอาร์ก ─▶ แผนตอน ─▶ ร่าง ─▶ ตรวจฉากหลัง/ลำดับเวลา/ภาษา ─▶ ตรวจทาน ─▶ อนุมัติ ─▶ คอมมิต
 (1 ครั้ง)   (อนุมัติ)           (อนุมัติ)     (อัตโนมัติ)         แก้การละเมิด hard             advisory   ผู้ใช้     Markdown
```

การออกแบบงานเขียนคือขั้นที่สร้างโลกและตัวละคร อนุมัติเรื่องทั้งหมด (StorySpine) และอนุมัติสกิลนักเขียนเฉพาะของงานเขียน (WriterSkill)
การเขียนจะเริ่มหลังจากขั้นนี้เสร็จ การตรวจภาษาของงานเขียนใช้กับงานเขียนทุกเรื่อง รวมถึงงานภาษาเกาหลี

เมื่อต้นฉบับและหลักฐานการตรวจทานมาถึง ตอบว่า "อนุมัติ" หรือ "แก้ตรงนี้แล้วลองใหม่" โหมด `auto` จะคอมมิต
อัตโนมัติเมื่อผ่านการตรวจที่บังคับและการตรวจทานเสร็จตามปกติ advisory จากการตรวจทานถูกบันทึกไว้แต่ไม่ขวางการคอมมิต
และหากการตรวจทานไม่เสร็จ ร่างจะกลับไปรอการอนุมัติ เว็บตูนก็ใช้ประโยคเดียว

> ทำตอนที่ 1 เป็นเว็บตูน ถามทิศทางการผลิตก่อน

```text
ช่วงต้นฉบับ·ลายเส้น·ภาพอ้างอิง·จำนวนช่อง·โมเดลภาพ ─▶ กำกับฉาก ─▶ ตรวจก่อนสร้าง ─▶ ภาพฉากพร้อมบทพูด ─▶ ตรวจภาพ
 (ผู้ใช้เลือก)                                     (ภาษาอังกฤษ) บล็อก hard     บทพูดเป็นต้นฉบับภาษาของงาน ไม่ผ่านจะออกแบบใหม่อัตโนมัติ
```

จำนวนช่องเป็นจำนวนเต็ม (1–12) หรือ `auto` และภาพอ้างอิงคือไฟล์ภาพตัวละครและฉากหลังที่ผู้ใช้ระบุเอง
โมเดลภาพเลือกจากโมเดลของ OpenAI API ได้แก่ `gpt-image-2`, `gpt-image-2.5-sunburst` (ค่าเริ่มต้น) และ `gpt-image-2.5-flare`
โดยโฮสต์เป็นผู้เรียก หากไม่ผ่านการตรวจก่อนสร้างหรือการตรวจภาพ จะออกแบบใหม่จากข้อบกพร่องแล้วสร้างอีกครั้ง
(ค่าเริ่มต้น 2 ครั้ง สูงสุด 3 ครั้ง และทุกครั้งมีค่าใช้จ่ายภาพ) ผลลัพธ์คือภาพฉากและ `scene.html`
อยู่ใต้ `.vibelore/webtoon/candidates/`

## การติดตั้ง

ส่งที่อยู่ของรีโพสิทอรีให้เครื่องมือเขียนโค้ดด้วย AI ที่คุณใช้ (Claude Code, Codex, Grok CLI) แล้วขอให้ช่วย

> ดาวน์โหลด https://github.com/fbwndrud/vibelore แล้วลงทะเบียนเป็นเซิร์ฟเวอร์ MCP ให้หน่อย

ที่ต้องมีคือ Node.js 22.13 ขึ้นไป (22.x), 24.x หรือ 26.x เท่านั้น ไม่มีการบิลด์และไม่ต้องติดตั้ง dependency
เมื่อลงทะเบียนเสร็จ ให้รีสตาร์ตเครื่องมือ AI หนึ่งครั้ง

<details>
<summary>ลงทะเบียนด้วย npm</summary>

รันเซิร์ฟเวอร์ MCP จากแพ็กเกจ npm [`vibelore`](https://www.npmjs.com/package/vibelore) โดยไม่ต้องดาวน์โหลดรีโพสิทอรี

```bash
claude mcp add-json vibelore '{"command":"npx","args":["-y","vibelore"]}' --scope project
```

สำหรับ Codex คือ `command = "npx"`, `args = ["-y", "vibelore"]` และ Grok CLI คือ `grok mcp add vibelore -- npx -y vibelore`
บน Windows ให้ใส่ `cmd /c` หน้า `npx` (`"command":"cmd","args":["/c","npx","-y","vibelore"]`)
หากต้องการตรึงเวอร์ชัน ให้เขียนแบบ `vibelore@<เวอร์ชัน>` วิธี npm ลงทะเบียนเฉพาะเซิร์ฟเวอร์ MCP ดังนั้นให้ติดตั้งสกิลสัมภาษณ์
ด้วยวิธีรีโพสิทอรีด้านล่างหรือปลั๊กอิน Codex
</details>

<details>
<summary>ดาวน์โหลดรีโพสิทอรีแล้วลงทะเบียนเอง</summary>

```bash
git clone https://github.com/fbwndrud/vibelore.git
```

Claude Code:

```bash
claude mcp add-json vibelore '{"command":"node","args":["/absolute/path/to/vibelore/src/server.js"]}' --scope project
```

Codex (`~/.codex/config.toml`):

```toml
[mcp_servers.vibelore]
command = "node"
args = ["/absolute/path/to/vibelore/src/server.js"]
startup_timeout_sec = 30
tool_timeout_sec = 6000
```

Grok CLI:

```bash
grok mcp add vibelore -- node /absolute/path/to/vibelore/src/server.js
```

สำหรับ Claude Code สกิลลูปการเขียนอยู่ใน `hosts/claude/skills/novel/` ส่วนสกิลสัมภาษณ์งานเขียนและเว็บตูนอยู่ใน `skills/story-discovery-interview/` และ `skills/webtoon-discovery-interview/` คัดลอกทั้งหมดไปไว้ใต้ `.claude/skills/` รีโพสิทอรีนี้ติดตั้งเป็นปลั๊กอิน Codex (`.codex-plugin/plugin.json`) ได้ด้วย
</details>

ติดตั้งเสร็จแล้วก็เริ่มงานเขียนเรื่องแรกได้เลย แค่เล่าเรื่องที่อยากเขียนในหนึ่งหรือสองประโยค

> อยากเริ่มนิยายเรื่องใหม่ เป็นเรื่องของคนขับรถเมล์กะดึกที่รับฟังความเสียใจของผู้โดยสาร เริ่มจากการสัมภาษณ์งานเขียนก่อนเลย

การสัมภาษณ์จะถามเฉพาะความชอบที่เปลี่ยนผลลัพธ์ ครั้งละ 4–5 ข้อ หากต้องการข้าม ให้พูดว่า "ไม่ต้องถาม ตัดสินใจ
อัตโนมัติเลย" หากติดขัด ดู[คู่มือเริ่มต้น](docs/GETTING_STARTED.en.md)

## ทำอะไรให้บ้าง

- **สัมภาษณ์งานเขียน** แทนที่จะถามชื่อประเภท จะถามถึงจังหวะ ความยาก อารมณ์ รางวัลที่ผู้อ่านได้รับ และข้อห้าม เพื่อสร้างสัญญาการอ่าน (StoryProfile) แล้วสร้างโลกและตัวละครโดยอัตโนมัติ
- **ออกแบบอาร์ก** ขออนุมัติคำสัญญาในหน่วย 3–20 ตอน พร้อมเหตุการณ์ แรงกดดัน และจุดเปลี่ยนแบบคร่าว ๆ ก่อน ส่วนแผนรายตอนจะเติมให้อัตโนมัติตอนเขียน
- **ตรวจและแก้ทุกตอน** เทียบร่างกับตัวละคร คำเรียกขาน มุมมอง ลำดับเวลา และปม หากขัดกับข้อเท็จจริงที่ยืนยันแล้วจะแก้และตรวจซ้ำอัตโนมัติ (ตรวจสูงสุด 3 ครั้ง แก้ระหว่างนั้นสูงสุด 2 ครั้ง) ข้อสังเกตเชิงรสนิยมอย่างสำนวนหรือจังหวะจะเก็บไว้เป็น advisory เท่านั้น
- **มาตรฐานสำนวน** ถ้ากำหนดตอนที่ชอบเป็นหมุดสำนวน ตอนต่อ ๆ ไปจะเดินตามเนื้อสัมผัสนั้น
- **ย้อนกลับ** ย้อนทั้งเรื่องกลับไปยังจุดของตอนที่กำหนด แล้วเขียนใหม่ตั้งแต่ตอนถัดไป (สถานะก่อนย้อนกลับถูกเก็บไว้ให้กู้คืนได้)
- **ดัดแปลงเป็นเว็บตูน** ดึงสถานะจากต้นฉบับ ยืนยันช่วงของต้นฉบับ ลายเส้น ภาพอ้างอิง จำนวนช่อง และโมเดลภาพ แล้วทำแต่ละฉากให้เสร็จเป็นภาพเดียวรวมบทพูด

**สิ่งที่ไม่ทำ** GUI บนเว็บ (ช่องแชตของโฮสต์คืออินเทอร์เฟซ) การเรียก API แบบเสียเงินโดยตัวเซิร์ฟเวอร์ MCP เอง (API ภาพ
โฮสต์เป็นผู้รัน) การเขียนตอนก่อนหน้าใหม่หรือคำนวณสถานะหลังจากนั้นใหม่ด้วยเครื่องมือเริ่มต้น (ทำได้เฉพาะเครื่องมือกู้คืน
`lore_rewrite` และ `lore_refold` ของ `VIBELORE_MCP_SURFACE=advanced`) การรับประกันคุณภาพทางวรรณกรรม
การแก้ไขพร้อมกันหรือหลายผู้เช่า และการตัดแบ่งเป็น PNG/JPEG สำหรับแพลตฟอร์มโดยอัตโนมัติ

## ภาษาของงานเขียน

จะเขียนงานด้วยภาษาใดกำหนดด้วยอาร์กิวเมนต์เสริม `language` ที่ `lore_profile`, `lore_init`
และ `lore_create` รับได้ (`language` ของ `lore_write` ใช้ยืนยันเพียงว่าตรงกับภาษาที่บันทึกไว้) เมื่อผู้ใช้บอกภาษาที่จะเขียนเป็นภาษาธรรมชาติ โฮสต์จะแปลงเป็นแท็ก BCP 47
(`ja`, `pt-BR`, `zh-Hant` เป็นต้น) แล้วส่งต่อ หากไม่ได้เลือกภาษาก็ละอาร์กิวเมนต์นี้ไว้
งานเขียนเดิมที่ไม่มีคีย์ภาษาถือเป็น `ko` โดยนัย ภาษาที่ใช้สนทนากับภาษาของงานเขียนแยกจากกัน จึงสามารถ
สนทนาเป็นภาษาเกาหลีขณะเขียนงานภาษาญี่ปุ่นได้

> อยากสร้างงานเขียนชื่อ `harbor_summer` ใน `/absolute/path/to/my-novel` ช่วยเขียนเนื้อเรื่องเป็นภาษาสเปน

- พรอมต์มีสองชุด `ko` ใช้คำสั่งเฉพาะสำหรับภาษาเกาหลี ส่วนภาษาอื่น (รวมภาษาอังกฤษ) ใช้ชุดที่รวมคำสั่งกลาง
  ภาษาอังกฤษเข้ากับภาษาเป้าหมาย เนื้อเรื่อง ชื่อตอน บทสรุป คำอธิบายโลกและตัวละคร และค่าคำอธิบายในแผนและการตรวจทาน
  จะเป็นภาษาเป้าหมาย ส่วนค่าที่เครื่องอ่าน เช่น คีย์ JSON, enum และ ID จะไม่แปล
- ความยาววัดด้วยหน่วยที่เหมาะกับภาษา ภาษาเกาหลีใช้จำนวนตัวอักษรแบบเดิม ภาษาอื่นใช้กราฟีม (grapheme)
  หรือจำนวนคำ และระบบการเขียนที่มีอักขระประกอบมากอย่างภาษาอาหรับและฮีบรู รวมถึงภาษาไทยที่ไม่เว้นวรรคระหว่างคำ
  ก็จัดการภายใต้สัญญาเดียวกัน
- ก่อนสร้าง foundation เปลี่ยนภาษาได้ด้วยการอนุมัติ revision ใหม่ของโปรไฟล์ และหากส่งค่าที่ต่างจากภาษาที่อนุมัติแล้ว
  จะปฏิเสธด้วย `LANGUAGE_CONTRACT_CONFLICT` หลังจากสร้าง foundation แล้วเปลี่ยนไม่ได้ หากส่งค่าที่ต่างออกไป
  จะไม่เขียนทับอย่างเงียบ ๆ แต่จะปฏิเสธด้วย `WORK_LANGUAGE_IMMUTABLE`
- ทุกตอนจะตรวจว่าเนื้อเรื่อง บทสรุป และแผนเขียนด้วยภาษาของงานเขียนหรือไม่ ส่วนเงื่อนไขคงที่เชิงความหมาย
  อย่างมุมมอง การลงทะเบียนตัวละคร และฉากหลังของโลก ผู้ตรวจคนเดียวกันจะดูโดยไม่ขึ้นกับภาษา
- เว็บตูนก็ใช้ภาษาของงานเขียนเช่นกัน บทพูดไม่ถูกแปล แต่ใส่ลงในภาพเป็นต้นฉบับในภาษาของงานเขียน
  และพรอมต์ภาพจะระบุภาษา ระบบตัวอักษร และทิศทางการอ่าน (ภาษาอาหรับอ่านจากขวาไปซ้าย)

การเขียนนิยายและขั้นตอนเว็บตูนแบบรายฉากได้รับการยืนยันด้วยชุดตัวอย่างสำหรับการตรวจรับใน 8 ภาษา ได้แก่ อังกฤษ สเปน
ญี่ปุ่น ฝรั่งเศส เกาหลี อาหรับ จีนตัวเต็ม และไทย โมเดลโฮสต์ของชุดตัวอย่างนี้คือ Claude Sonnet 5 รายละเอียดของสัญญา
อาร์กิวเมนต์ ดู[ภาษาของงานเขียนและหน่วยความยาว](docs/TOOLS.en.md#work-language-and-length-units)

## โมเดลและค่าใช้จ่าย

- **นิยาย** เขียนโดยโมเดลที่คุณเลือกในเซสชันของโฮสต์ ไม่ต้องใช้ API key แยก ให้คำแนะนำรายขั้นตอนที่มอบขั้นวางแผน ร่าง และตรวจทานให้โมเดลที่เบากว่าได้ (ในการรีเลย์ผ่านโฮสต์เป็นเพียงคำแนะนำ มีเพียงโมเดลโลคัลที่สลับจริง) ส่วนขั้นที่ดึงข้อเท็จจริงที่ยืนยันแล้วยังคงใช้โมเดลหลักหากไม่ได้กำหนดแยก
- **ภาพเว็บตูน** สร้างด้วย OpenAI image API (`gpt-image-2`, `gpt-image-2.5-sunburst` (ค่าเริ่มต้น), `gpt-image-2.5-flare`) ที่โฮสต์เรียก และมี key และการเรียกเก็บเงินแยก โมเดลที่ยืนยันแล้วจะบันทึกแยกตามงานเขียนและไม่เปลี่ยนหรือแทนที่เอง
- **โมเดลข้อความแบบโลคัล** เชื่อมต่อกับเอ็นด์พอยต์ที่เข้ากันได้กับ OpenAI ผ่านตัวแปรสภาพแวดล้อมได้

การตั้งค่าโดยละเอียด ดู[การตั้งค่าโมเดล](docs/MODELS.en.md)

<summary>ถ้าหยุดกลางคัน ต้องเริ่มใหม่ทั้งหมดไหม</summary>

ไม่ต้อง เวิร์กโฟลว์ถูกบันทึกไว้ พูดว่า "ทำต่อ" ก็กลับมาทำต่อจากจุดเดิม คอมมิตเฉพาะต้นฉบับที่ผ่านการตรวจ และย้อนกลับได้ด้วยสแนปชอตรายตอน ดู[การแก้ปัญหา](docs/TROUBLESHOOTING.en.md#work-stopped-midway)
</details>

<details>
<summary>แก้ฉากหลังหรือเนื้อเรื่องด้วยมือได้ไหม</summary>

ได้ `world/`, `characters/` และ `chapters/` มีไว้ให้คนแก้ แก้เสร็จแล้วพูดว่า "ตรวจการเปลี่ยนแปลงให้หน่อย" ก็จะบอกขอบเขตผลกระทบและสิ่งที่ต้องทำต่อ
</details>

<details>
<summary>ถ้าสิ่งที่ตัวตรวจจับได้ จริง ๆ แล้วเป็นจุดหักมุมที่ตั้งใจไว้ล่ะ</summary>

การละเมิดแบบ hard คือความขัดแย้งกับข้อเท็จจริงที่ยืนยันแล้วจึงถูกแก้ แต่ถ้าเป็นจุดหักมุมจริง ให้แก้ไฟล์ฉากหลังก่อน การละเมิดแบบ soft อาจเป็นความตั้งใจของผู้เขียน AI จึงไม่แก้อัตโนมัติและจะถามคุณ
</details>

<details>
<summary>เขียนด้วยภาษาอื่นนอกจากภาษาเกาหลีได้ไหม</summary>

ได้ ภาษาที่ใช้เขียนกำหนดตอนสร้างงานเขียน (ในโปรไฟล์หรือด้วย `lore_create`/`lore_init`) และการสัมภาษณ์ดำเนินด้วยภาษาที่คุณใช้ เอกสารคู่มือมีต้นฉบับภาษาเกาหลีและฉบับภาษาอังกฤษ (`*.en.md`) ดู[ภาษาของงานเขียน](#ภาษาของงานเขียน)ด้านบน
</details>
