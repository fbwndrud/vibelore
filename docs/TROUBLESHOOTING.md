# 문제 해결과 백업

같은 생성 요청을 처음부터 반복하기 전에 **현재 작업이 어디서 멈췄는지** 확인하세요.
상태·승인·후보가 남아 있다면 같은 작업을 이어갈 수 있습니다.

## 도구가 보이지 않아요

1. [시작 안내](GETTING_STARTED.md)의 서버 등록 경로가 실제 설치 위치인지 확인합니다.
2. 실행 환경에 Node.js 22.13.0 이상인 22.x 또는 24.x가 있는지 확인합니다.
3. 연결한 AI 앱/CLI에서 MCP 설정을 다시 읽거나 새 세션을 엽니다.
4. “vibelore 연결과 작품 상태를 확인해 줘”라고 요청합니다.

문제가 계속되면 [연결 진단](OPERATIONS.md#연결-문제)을 참고해 오류 메시지와 함께 문의하세요.
키·전체 원고·개인 경로는 공개 이슈에 그대로 올리지 마세요.

## 작업이 멈췄어요

소설이라면:

> `night_bus`의 진행 중인 소설 작업 상태와 대기 이유를 확인하고, 저장된 작업에서 이어가 줘.

웹툰이라면:

> `night_bus`의 진행 중인 **웹툰 작업**을 확인해 줘. 완료된 이미지와 남은 요청을 확인하고 같은 작업에서 이어가 줘.

| 보이는 상태 | 뜻 | 사용자가 할 일 |
|---|---|---|
| 모델 응답 대기 (`needs_model`) | AI가 처리할 계획·집필·검토 요청이 있음 | 같은 요청에 답해 이어가 달라고 하기 |
| 인터뷰·승인 대기 | 사용자 결정이 필요함 | 질문에 답하거나 실제 결과를 보고 승인·수정·보류 선택 |
| 이미지 실행 대기 | 선택 모델·도구·키·권한 등을 확인해야 함 | 실행 가능한 경로와 비용을 확인하고 선택 |
| 검토 실패 | 검토가 끝나지 않았거나 확인할 문제가 있음 | 실패 이유와 보존된 결과를 먼저 보여 달라고 하기 |
| 문자 배치 실패 (`layout_blocked`) | 배치 검사에서 문제를 발견함 | 얼굴 가림·순서·글자 등 문제가 있는 부분의 재배치 요청 |
| 다른 작업이 사용 중 (`PROJECT_BUSY`, `WEBTOON_BUSY`) | 같은 작품을 다른 실행이 수정 중임 | 해당 실행이 끝난 후 재개; 잠금 파일은 직접 삭제하지 않기 |

앱이 닫힌 동안 vibelore가 배경에서 계속 생성하지는 않습니다. 작업을 다시 연결해 진행해야 합니다.
이미지 서비스가 생성은 끝냈지만 파일 반입 전에 중단됐을 수 있으므로,
재시도 전에 결과 파일을 확인해 불필요한 중복 과금을 피하세요.

## 검토는 끝났는데 내용이나 그림이 어색해요

검사 통과는 모든 의미·연출 문제를 찾았다는 보증이 아닙니다. 어색한 곳과 의도한 결과를
함께 알려 주면 수정 범위를 정하기 쉽습니다.

> 이 대사는 앞 질문에 대한 답이 아니야. 원작의 앞뒤 문맥을 확인하고 해당 대화만 수정해 줘.

> 전투에서 적이 갑자기 반대편으로 옮겨 갔어. 연결되는 컷의 동선부터 다시 확인하고, 다시 그릴 범위를 먼저 알려 줘.

웹툰은 대본, 구도, 그림, 문자 배치를 구분해 수정합니다. 말풍선 위치만 문제라면
그림 전체를 재생성할 필요는 없습니다. [웹툰 수정 안내](WEBTOON.md#수정하거나-이어서-만들기)를 보세요.

## 원고나 설정 파일을 직접 고쳤어요

> 원고와 설정을 손으로 수정했어. 변경 내용을 먼저 확인하고, 필요한 검사와 동기화 절차를 안내해 줘. 아직 다음 화는 쓰지 마.

마지막 화, 앞 화, 세계·인물 설정은 영향 범위가 다릅니다. 특히 앞 화를 고친 뒤에는 이후
상태 재계산이 필요할 수 있으며, 뒤 화 원고가 자동으로 다시 쓰이는 것은 아닙니다.
고급 복구가 필요하면 AI가 먼저 해당 절차와 영향을 설명하도록 하세요.

웹툰 제작 중 원작을 고쳐도 고정된 각색 입력이 자동 교체되지 않습니다. 웹툰 대본을 손으로
수정했다면 변경 의도를 알리고 재검토를 요청하세요. `.vibelore/`의 상태나 승인 기록은 직접
고치지 않습니다.

## 소설을 이전 시점으로 되돌리고 싶어요

> `night_bus`를 5화 시점으로 되돌릴 수 있는지 확인해 줘. 보관할 현재 파일과 복구 후 달라질 범위를 먼저 보여 줘.

복구 가능한 스냅샷과 영향을 확인한 뒤 진행합니다. 현재 상태는 보관 영역으로 옮기지만,
이 기능을 별도 백업 대신 사용하지 마세요. 소설을 되돌려도 기존 웹툰의 원작 판본과 결과는
별도로 남습니다. 웹툰도 같은 시점으로 되돌리는 명령은 아닙니다.

## 무엇을 백업해야 하나요?

작업 중인 AI와 서버를 멈춘 뒤 **작품 폴더 전체를 숨김 폴더까지 포함해 별도 위치에 복사**하세요.

- `world/`, `characters/`, `chapters/`, `summaries/`: 원작 설정과 원고
- `webtoon/`: 승인된 웹툰 대본·기준 이미지·완성본
- `.vibelore/`: 진행 중 후보·검토·승인·재개·복구 기록
- 직접 보관한 원본 그림과 참조 파일이 있는 폴더

원고만 복사하면 진행 중 작업과 검토 이력까지 복원할 수 없습니다.
Git을 백업 수단으로 사용한다면 숨김 폴더와 이미지가 제외되고 있지 않은지 확인하세요.
API 키 같은 비밀 값은 공개 저장소에 넣지 않습니다.

상태 코드와 수동 복구가 필요할 때만 [운영·복구 상세 절차](OPERATIONS.md)를 참고하세요.
