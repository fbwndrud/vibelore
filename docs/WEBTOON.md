# 기존 소설로 웹툰 만들기

vibelore에 있는 소설·세계관·인물을 바탕으로 **세로 스크롤 웹툰 한 회차**를 만듭니다.
원작에서 살릴 장면을 고르고, 웹툰 대본과 구도 러프를 확인한 다음 그림과 글자를 합칩니다.
소설 원고는 그대로 두고 웹툰 결과를 별도로 저장합니다.

이 안내는 0.3.2에서 제공하는 제작 흐름을 다룹니다. 도구 호출 코드를 직접 작성할 필요는
없습니다. 연결한 AI에게 아래 예시처럼 요청하세요.

## 시작 전에 준비할 것

- **vibelore 연결:** [시작 안내](GETTING_STARTED.md)에 따라 설치하고 AI에서 도구가 보이는지 확인합니다.
- **원작:** vibelore로 초기화된 작품 폴더, 작품 ID, 웹툰으로 만들 원작 화가 필요합니다.
  일반 텍스트 파일만 있다면 먼저 [기존 작품 이어받기](GETTING_STARTED.md#7-이미-있는-작품-이어받기)를 진행합니다.
- **이미지 작업 환경:** 연결한 AI가 이미지를 생성·수정하고, 참조 이미지와 완성 그림을 열어 볼 수 있어야 합니다.
  MCP 연결만으로 이미지 생성 기능이 생기지는 않습니다.
- **이미지 실행 선택:** 사용할 모델과 내장 도구/API 경로를 확인합니다. API를 선택하면
  별도 키·계정 권한·과금이 필요합니다. 키는 채팅에 붙이지 말고 실행 환경에 설정하세요.

현재 결과물은 세로형 SVG와 HTML입니다. 업로드용 PNG/JPEG가 필요하다면 완성본을
별도로 변환·분할해야 합니다. 원고와 이미지는 로컬에 보관하지만, 생성·검토에 필요한
자료는 연결한 AI 서비스에 전달될 수 있습니다. [데이터와 보안](../SECURITY.md)을 확인하세요.

## 이렇게 요청하세요

아래 작품 경로와 ID를 자신의 것으로 바꿔 요청합니다. 원작 화와 웹툰 회차를 구분해 주세요.

> `/absolute/path/to/my-novel`의 작품 `night_bus` 원작 1화를 웹툰 1화로 만들어 줘. 원작 설정을 읽고, 각색 방향과 작화·문자 표현부터 물어봐 줘. 장면별로 나눠 제작하고 러프를 보여준 뒤 작화로 진행해.

원작 여러 화를 한 웹툰 회차로 묶을 수도 있습니다. 예를 들어 “원작 1~2화를 웹툰 1화로”라고
지정하세요. 한 작품에서는 한 웹툰 회차씩 진행합니다.

MCP만 수동 등록해 인터뷰 스킬이 로드되지 않았다면 다음 요청을 한 번 덧붙입니다.

> vibelore 설치 폴더의 `skills/webtoon-discovery-interview/SKILL.md`를 읽고 그 절차로 진행해.

## 처음에 무엇을 정하나요?

인물 이름·관계·세계 규칙은 원작에서 가져옵니다. 인터뷰에서는 새로 이야기를 만드는 대신,
**무엇을 강조하고 어떤 모습으로 보여줄지** 정합니다.

| 선택 | 답변 예시 | 적용되는 곳 |
|---|---|---|
| 이번 화의 핵심과 각색 범위 | “귀환의 낯섦이 중심이야. 설명은 줄이되 딸을 찾는 동기는 남겨.” | 남길 장면, 압축·생략할 장면, 대본 |
| 작화 | “선명한 컬러, 자연스러운 인체, 표정은 조금 과장해.” | 인물·배경 기준 이미지와 컷 생성 지시 |
| 문자 표현 | “속생각은 밝은 상자로, 실제 대사는 말풍선으로.” | 대사·독백·설명·효과음 표시 |
| 읽는 형식 | “세로 스크롤로 읽게 해 줘.” | 컷의 세로 배치와 여백 |
| 제작 제약 | “이미지 모델과 과금 경로를 먼저 확인하고, 재생성 비용이 생기면 알려 줘.” | 실행 선택과 제작 진행 지침 |

문자 표현은 **기본 대비형**(짙은 독백 상자), **밝은 상자형**, **상자 최소형** 중 고르거나
지원 범위 안에서 조합할 수 있습니다. 작화 취향은 이미지 생성 지시이므로 결과가 취향에
맞는지는 기준 이미지를 보고 확인해야 합니다.

“알아서 진행해”라고 해도 새 작업의 작화·문자·읽는 형식 선택과 러프 승인은 직접 확인합니다.
같은 작품에서 이미 확정한 선택은 다음 회차에 재사용합니다. 이미지 모델·실행 경로도 사용자
확인 후 작품별로 유지하며, 실행할 수 없다고 다른 모델이나 유료 경로로 자동 전환하지 않습니다.
서버가 제시하는 모델 목록은 계정에서 사용 가능하다는 보증이 아닙니다.

## 어떤 결과를 확인하게 되나요?

기본 검토 모드에서는 다음 순서로 결과를 보여주고 승인을 받습니다. 문제가 있으면
그 단계에서 수정 방향을 말하세요. 앞 단계의 승인이 최종본 승인까지 대신하지는 않습니다.

| 단계 | 받는 결과 | 확인할 것 |
|---|---|---|
| 1. 제작 방향 | 원작에서 가져온 설정과 인터뷰 정리 | 원하는 독자 경험·화풍·각색 범위인가? |
| 2. 각색 | 장면 선별안, 컷 순서, 실제 대사, 대본 콘티 | 소설을 읽지 않아도 동기와 사건이 이어지는가? |
| 3. 시각 기준 | 이번 회차에 필요한 인물·의상·공간 이미지 | 같은 인물로 보이는가? 외형과 분위기가 맞는가? |
| 4. 구도 러프 | 단순한 인물·소품·동선으로 그린 컷 묶음 | 누가 어디서 무엇을 하고 다음 컷으로 어떻게 이어지는가? |
| 5. 작화·문자 합성 | 실제 그림에 대사·독백·효과음을 붙인 검토본 | 동작·시선·말풍선 꼬리·읽는 순서가 자연스러운가? |
| 6. 최종본 | 모든 컷이 들어간 SVG·HTML | 한 화 전체의 흐름과 마무리가 만족스러운가? |

대본 콘티는 그림 완성본이 아닙니다. 구도 러프도 얼굴·채색 품질보다 **배치와 동작**을
확인하기 위한 것입니다. 러프를 승인해야 본 작화를 시작합니다.

컷 수는 원작을 얼마나 덜어내고 무엇을 강조하는지에 따라 정합니다. 기본 40컷은 제작 상한이지
채워야 할 분량이 아닙니다. 장면별 제작에서는 전체 방향과 앞뒤 문맥을 유지하면서 작은 묶음으로
각색·검토하고, 마지막에 전체 흐름을 다시 확인합니다.

## 그림과 글자는 어떻게 다루나요?

**연속성은 같은 구도를 반복한다는 뜻이 아닙니다.** 식사처럼 자세·좌석·소품을 이어야 하는
컷은 검토된 앞 그림을 참조합니다. 액션의 새 구도는 승인 러프와 인물 기준에서 만들고,
완성된 앞뒤 그림의 동작과 결과가 이어지는지 비교합니다. 독립된 작업은 호스트 환경이 허용하면
병렬로 진행하지만, 앞 그림이 필요한 컷은 기다립니다. 자세한 구조는 [아키텍처](ARCHITECTURE.md#웹툰-제작-구조)를 보세요.

| 문자 종류 | 만드는 방식 | 수정 방법 |
|---|---|---|
| 실제 대사 | 화자를 지정하고 그림 위에 말풍선 배치 | 문구 변경 또는 말풍선 배치 수정 요청 |
| 속생각·설명 | 대사와 구분해 상자 또는 상자 없는 글자로 배치 | 역할·문구·표시 방식 수정 요청 |
| 효과음 | 소리가 나는 위치를 기준으로 별도 배치 | 발생 위치·크기·강조 수정 요청 |
| 간판·모니터·문서의 글자 | 해당 사물 표면에 이미지로 생성 | 잘못된 글자가 있는 그림 부분 수정 요청 |

말풍선 겹침과 글자 크기 등은 코드로 검사하지만, 화자·동작의 의미와 자연스러움은 AI의
이미지 검토와 사용자 확인이 필요합니다. 검사 완료가 모든 연출 오류를 잡았다는 뜻은 아닙니다.

## 완성본은 어디에 있나요?

최종 승인 후 작품 폴더의 다음 위치에 저장합니다. `회차-작업ID` 부분은 실제 작업마다 다릅니다.

```text
my-novel/
├── chapters/                    원작 소설 — 웹툰 제작으로 덮어쓰지 않음
├── webtoon/
│   ├── profile.md               승인한 웹툰 제작 방향
│   ├── references/              승인한 인물·공간 기준 이미지
│   └── episodes/회차-작업ID/
│       ├── editorial.md         장면 선별 이유
│       ├── script.md            컷별 행동과 대사
│       ├── plan.json            구조화된 각색 계획
│       ├── episode.html         브라우저로 보는 완성본
│       ├── episode.svg          세로형 이미지 마스터
│       └── lettering.json       문자 원문과 배치 정보
└── .vibelore/                   후보·진행·검토·승인 기록
```

> 웹툰 1화의 최종 승인 여부를 확인하고, 승인된 HTML 완성본과 SVG 파일을 열어 줘.

검토 도중에는 후보 파일을 보게 됩니다. **후보가 생성된 것과 최종 승인본이 저장된 것은 다릅니다.**
SVG의 글자는 표시가 달라지지 않도록 윤곽선으로 저장하므로, 문구를 고칠 때는 SVG 안의 글자를
직접 편집하기보다 대본 수정과 재조판을 요청하세요. 외부 서비스에 자동 게시하지는 않습니다.

## 러프 없이 장면 전체를 한 번에 그리기

컷별 러프 대신 **장면 한 덩어리를 대사까지 포함해 한 장으로** 생성하는 경로도 있습니다.
원작 문단 범위를 정하고, 영어 연출 브리프 → 생성 전 검증 → 장면 이미지 → 실제 그림 검토 순서로 진행합니다.
이미 승인한 이미지 API 선택과 인물·배경 참조 이미지를 그대로 씁니다.

시작할 때 **칸 수**를 묻습니다. 선택지는 `4, 6, 8, 9, auto`이며 다른 정수(1~12)도 말할 수 있습니다.

- 정수를 고르면 그 칸 수로 고정하고, 실제 그림의 칸 수가 다르면 완료 처리하지 않습니다.
- `auto`를 고르면 각색할 때마다 AI가 3~12칸 중 적정 수를 새로 정합니다. 수정 요청 뒤에도 다시 고릅니다.
- 1~2칸은 가능하지만 앞뒤 장면과의 연속성이 잘 지켜지지 않을 수 있다는 경고가 함께 돌아옵니다. 3칸 이상을 권합니다.

칸 크기·배치·카메라는 이미지 모델이 정합니다. 글자가 그림 안에 들어가므로 문구를 고치려면 재생성이 필요합니다.
앞 장면을 지정해 이어 그리면 인물·배경·동작 연결을 실제 두 그림으로 비교해 검토합니다.

> `night_bus` 원작 1화 첫 장면을 러프 없이 한 장으로 그려 줘. 칸 수는 auto로 하고, 앞 장면이 있으면 이어서 검토해 줘.

## 수정하거나 이어서 만들기

진행 중인 회차는 다음처럼 **어떤 부분을 바꿀지** 말하면 됩니다.

- 각색: “도망가라고 말한 다음 왜 적에게 다가가는지 이해가 안 돼. 앞뒤 행동과 대사를 다시 잡아 줘.”
- 러프: “이 세 컷에서 인물의 이동 방향과 몬스터 위치가 이어지게 구도를 고쳐 줘.”
- 그림: “이 컷의 손과 무기 접점만 고치고 인물 디자인은 유지해.”
- 문자 배치: “그림과 대사는 그대로 두고, 말풍선이 얼굴을 가리지 않게 옮겨 줘.”

수정 범위에 따라 다시 검토할 단계가 달라집니다. 그림 입력이 변하지 않은 컷은 재사용할 수 있지만,
참조하는 앞 그림이나 구도가 바뀌면 관련 컷도 다시 검토합니다. 재생성이 필요한 범위를 먼저
확인하면 불필요한 이미지 호출을 줄일 수 있습니다.

중간에 멈췄다면:

> `night_bus`의 진행 중인 **웹툰** 작업 상태를 확인하고, 남은 단계부터 이어가 줘. 새 작업을 중복 생성하지 마.

다음 회차를 시작하려면:

> 웹툰 1화가 최종 승인됐는지 확인하고, 원작 2화로 웹툰 2화를 시작해. 기존 화풍과 유효한 승인 기준 이미지는 재사용해.

이미 완료한 회차의 재각색은 이전 승인본을 보존한 새 작업으로 진행합니다. 원작을 나중에
수정해도 제작 중인 웹툰의 원작 판본이 자동 교체되지는 않습니다. 새 원작으로 다시 만들려면
그 범위를 명시해 요청하세요.

문제가 생기면 [문제 해결과 백업](TROUBLESHOOTING.md), MCP를 직접 연동한다면
[웹툰 실행 규약](reference/WEBTOON_WORKFLOW.md)을 확인하세요.
