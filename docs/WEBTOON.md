# 기존 소설로 웹툰 만들기

한국어 | [English](WEBTOON.en.md)

vibelore로 쓴 소설을 **웹툰 장면**으로 옮깁니다. 인물 외모, 세계관, 그 화까지의 상황은
원작에서 그대로 가져옵니다. 소설 원고는 건드리지 않고 웹툰은 따로 저장합니다.

도구 호출 코드를 직접 쓸 필요는 없습니다. AI에게 아래 예시처럼 말하면 됩니다.

## 준비물

- **vibelore 연결:** [시작 안내](GETTING_STARTED.md)대로 설치하고 도구가 보이는지 확인합니다.
- **원작:** vibelore로 쓴 작품과 웹툰으로 만들 화. 다른 곳에서 쓴 소설이라면 먼저
  [이미 쓴 소설 이어받기](GETTING_STARTED.md#5-이미-쓴-소설-이어받기)를 합니다.
- **그림을 열어 볼 수 있는 AI:** 호스트가 이미지 API를 호출하고, 만든 그림을 열어 검토할 수 있어야 합니다.
  vibelore를 연결한다고 그림 기능이 생기지는 않습니다.
- **OpenAI 이미지 API:** 그림은 OpenAI 이미지 모델 `gpt-image-2`, `gpt-image-2.5-sunburst`(기본),
  `gpt-image-2.5-flare` 중 하나를 호스트가 API로 호출해 그립니다. AI 도구에 내장된 이미지 기능은 이 경로에서
  쓰지 않습니다. API는 별도 키와 과금이 필요합니다. 키는 채팅에 붙여 넣지 말고 실행 환경에 설정하세요.
- **참조 그림:** 인물·배경 참조 이미지 파일(PNG/JPEG)이 작품 폴더 안에 1장 이상 있어야 합니다.

완성본은 장면마다 대사까지 들어간 PNG/JPEG 이미지 한 장과 그 이미지를 보여 주는 `scene.html`입니다.
세로로 긴 한 장 같은 판형은 연출 지시로 정합니다. 플랫폼 업로드용으로 나누는 일은 따로 해야 합니다.
원고와 그림은 내 컴퓨터에 남지만, 그림을 만들고 검토하는 데 필요한 자료는 연결한 AI 서비스로
전달될 수 있습니다. [데이터와 보안](../SECURITY.md)을 확인하세요.

## 이렇게 요청하세요

> 1화를 웹툰으로 만들어 줘. 원작 설정을 읽고, 각색 방향과 그림체·글자 표현부터 물어봐 줘. 장면 전체를 대사까지 한 장으로 그려 줘.

여러 작품이 있으면 작품 폴더나 작품 이름을 같이 말하세요. “원작 1~2화를 웹툰 1화로”처럼
여러 화를 한 회차로 묶을 수도 있습니다. 한 작품에서는 웹툰 한 회차씩 진행합니다.

인터뷰 스킬이 로드되지 않았다면 이 한 줄을 덧붙입니다.

> vibelore 설치 폴더의 `skills/webtoon-discovery-interview/SKILL.md`를 읽고 그 절차로 진행해.

## 두 가지 제작 방식

| | 장면 통합 (기본) | 컷별 제작 (deprecated) |
|---|---|---|
| 그리는 단위 | 장면 하나를 대사까지 한 장에 | 컷 하나씩 |
| 러프 확인 | 없음 | 있음. 승인해야 본 그림으로 |
| 글자 | 그림 안에 함께 그림. 고치려면 다시 그려야 함 | 그림 위에 따로 얹음. 문구만 고치기 쉬움 |
| 어울리는 경우 | 빨리 한 화를 보고 싶을 때 | 연출을 하나하나 잡고 싶을 때 |

새 작업은 장면 통합 방식만 만듭니다. 컷별 제작은 이미 진행 중인 작업을 마무리할 때만 쓰며
새로 시작할 수 없습니다. [쇼케이스](https://fbwndrud.github.io/vibelore/showcase/) 작품들도
장면 통합 방식으로 만들었습니다.

## 처음에 정하는 것

인물 이름·관계·세계 규칙은 원작에서 가져옵니다. 인터뷰에서는 **무엇을 강조하고 어떻게
보여줄지**만 정합니다.

| 정하는 것 | 답변 예시 |
|---|---|
| 원작 범위와 각색의 핵심 | “1화 앞부분, 귀환의 낯섦이 중심이야. 설명은 줄이되 딸을 찾는 동기는 남겨.” |
| 그림체 | “선명한 컬러, 자연스러운 인체, 표정은 조금 과장해.” |
| 글자 표현·판형·배치 재량 | “속생각은 밝은 상자로, 실제 대사는 말풍선으로. 세로로 긴 한 장으로 그려.” |
| 참조 그림 | “인물은 `refs/hero.png`, 거리 배경은 `refs/street.png`를 써.” |
| 칸 수 | “auto로 해 줘.” |
| 이미지 모델과 비용 | “기본 모델로 하고, 다시 그릴 때마다 비용이 든다는 건 알고 있어.” |

글자 표현·판형·배치 재량은 따로 고르는 메뉴가 아니라 영어 연출 지시(`direction`)에 담깁니다.
AI가 답을 영어로 정리해 보여 주면 뜻이 맞는지 확인하세요.

“알아서 진행해”라고 해도 칸 수와 이미지 모델·비용은 직접 확인합니다. 이미지 모델은 한 번 정하면
이 작품의 다음 장면·회차에도 유지하며, 실행이 안 된다고 다른 모델로 몰래 바꾸지 않습니다.
참조 그림은 장면을 시작할 때마다 지정합니다.

## 장면 통합: 대사까지 한 장으로

원작 문단 범위를 장면으로 나누고, 장면마다 연출 지시 → 그리기 전 검증 → 그림 → 실제 그림
검토 순서로 진행합니다. 이미 정한 이미지 모델을 그대로 쓰고, 지정한 인물·배경 참조 그림을 따라 그립니다.

> 1화 첫 장면을 한 장으로 그려 줘. 칸 수는 auto로 하고, 앞 장면이 있으면 이어서 검토해 줘.

시작할 때 **칸 수**를 묻습니다. `4, 6, 8, 9, auto` 중에서 고르거나 1~12 사이 숫자를 말합니다.

- 숫자를 고르면 그 칸 수로 고정합니다. 그림의 칸 수가 다르면 완료로 치지 않습니다.
- `auto`를 고르면 장면마다 AI가 3~12칸 중에서 정합니다.
- 1~2칸도 되지만 앞뒤 장면과 이어지는 느낌이 약해질 수 있습니다. 3칸 이상을 권합니다.

칸 크기와 배치는 이미지 모델이 정합니다. 앞 장면을 지정하면 인물·배경·동작이 이어지는지 두
그림을 나란히 놓고 검토합니다. 그리기 전 검증이나 그림 검토가 불합격이면 AI가 결함을 근거로
다시 설계해 그립니다(기본 2회, 최대 3회, 회마다 이미지 비용 발생). 그래도 불합격이면 결과와 근거를
보여 주고 수정 방향을 묻습니다. 따로 승인하는 단계는 없으며, 검토를 통과하면 완료입니다.

## 컷별 제작 (deprecated): 단계마다 확인하는 것

이미 진행 중인 컷별 작업에만 해당합니다. 새 작업은 위 장면 통합 방식으로 만듭니다.

| 단계 | 보게 되는 것 | 확인할 것 |
|---|---|---|
| 1. 방향 | 원작에서 가져온 설정과 인터뷰 정리 | 원하는 분위기·그림체·각색 범위인가? |
| 2. 각색 | 살릴 장면, 컷 순서, 실제 대사 | 소설을 안 읽어도 이야기가 이어지는가? |
| 3. 기준 그림 | 이번 화의 인물·의상·장소 그림 | 같은 인물로 보이는가? |
| 4. 러프 | 인물·소품·동선만 간단히 그린 밑그림 | 누가 어디서 무엇을 하는지, 다음 컷으로 자연스럽게 이어지는가? |
| 5. 그림과 글자 | 완성 그림에 대사·독백·효과음을 얹은 검토본 | 동작·시선·말풍선 꼬리·읽는 순서가 자연스러운가? |
| 6. 최종본 | 모든 컷이 들어간 SVG·HTML | 한 화 전체의 흐름이 만족스러운가? |

문제가 있으면 그 단계에서 고칠 방향을 말하세요. 앞 단계를 승인했다고 최종본까지 승인한 것은
아닙니다. 러프는 얼굴이나 채색이 아니라 **배치와 동작**을 보는 단계입니다.

컷 수는 원작을 얼마나 덜어내느냐에 따라 정합니다. 기본 40컷은 상한일 뿐 채워야 할 분량이 아닙니다.

## 그림과 글자

**이어지는 장면은 앞 이미지를 참조합니다.** 직전 장면과 연결하면 검토를 마친 그 이미지를
함께 보고 인물·배경·동작 연속성을 확인한 뒤 그립니다. 컷별 제작(deprecated)은 새 구도가
필요한 액션 컷을 러프와 기준 그림에서 시작합니다. 자세한 구조는
[아키텍처](ARCHITECTURE.md#웹툰-제작-구조)를 보세요.

장면 통합 방식에서는 대사·속생각·효과음·간판 글자가 모두 이미지 모델이 그린 그림 안에 들어갑니다.
대사는 번역하지 않고 작품 언어 원문 그대로 넣습니다. 글자가 맞는지, 누가 말하는지는 AI가 실제 그림을
열어 검토합니다. 글자 하나를 고치려 해도 장면을 다시 그려야 하며 새 이미지 비용이 듭니다.

### 컷별 제작 (deprecated)의 글자

| 글자 종류 | 만드는 방식 | 고치는 방법 |
|---|---|---|
| 대사 | 화자를 정하고 그림 위에 말풍선 배치 | 문구나 말풍선 위치 수정 요청 |
| 속생각·설명 | 대사와 구분되는 상자 또는 상자 없는 글자 | 문구나 표시 방식 수정 요청 |
| 효과음 | 소리가 나는 자리에 따로 배치 | 위치·크기·강조 수정 요청 |
| 간판·모니터·문서 속 글자 | 그림의 일부로 생성 | 잘못된 부분의 그림 수정 요청 |

말풍선 겹침과 글자 크기는 코드로 검사합니다. 누가 말하는지, 동작이 자연스러운지는 AI의 그림
검토와 사용자 확인이 필요합니다. 검사를 통과했다고 모든 연출 문제가 없다는 뜻은 아닙니다.

## 완성본은 어디에 있나요?

장면 통합 작업의 결과는 작업 폴더 안 `.vibelore/webtoon/candidates/작업ID/r개정번호/`에
장면 이미지(PNG/JPEG), `scene.html`, 계획·검토 JSON으로 남습니다. `webtoon/` 폴더에는 아무것도 쓰지 않습니다. `개정번호`는 재설계·재시도마다
올라가며, `작업ID`는 작업마다 다릅니다.

```text
my-novel/
├── chapters/                    원작 소설 — 웹툰 제작으로 덮어쓰지 않음
└── .vibelore/
    └── webtoon/candidates/작업ID/r개정번호/
        ├── scene.png             대사까지 그려진 장면 이미지(JPEG이면 scene.jpg)
        ├── scene.html            장면 이미지와 검토 근거를 담은 확인용 페이지
        ├── scene-plan.json       장면 각색 계획
        └── image-review.json     실제 그림 검토 결과
```

컷별 제작(deprecated)은 각색·승인이 끝나면 `webtoon/episodes/회차-작업ID/`에
`episode.html`·`episode.svg`·`editorial.md`·`script.md`·`lettering.json`으로 저장됩니다.

> 웹툰 1화 진행 상태를 확인하고, 완성된 장면 HTML을 열어 줘.

검토 중에 보는 것도 같은 후보 파일입니다. 장면 글자는 그림 안에 있으므로 고칠 점을 말해 다시
그리게 하세요. 컷별 제작의 SVG·HTML 글자도 직접 편집하지 말고 대본 수정과 재생성을 요청하세요. 외부 서비스에 자동으로 올리지는 않습니다.

## 고치거나 이어서 만들기

진행 중인 회차는 **어디를 바꿀지** 말하면 됩니다.

장면 통합 작업은 “이 장면에서 다음 검토가 관측한 문제(칸 수, 글자, 연속성)를 고쳐 다시 그려 줘”처럼
말하면 그 피드백으로 새로 각색·검증·생성합니다(매번 새 이미지 비용). 자동 재설계 횟수는 검증·검토
불합격에만 쓰입니다.

컷별 제작(deprecated)은 다음처럼 범위를 구분해 요청합니다.

- 각색: “도망가라고 말한 다음 왜 적에게 다가가는지 이해가 안 돼. 앞뒤 행동과 대사를 다시 잡아 줘.”
- 러프: “이 세 컷에서 인물의 이동 방향과 몬스터 위치가 이어지게 구도를 고쳐 줘.”
- 그림: “이 컷의 손과 무기 잡는 부분만 고치고 인물 디자인은 유지해.”
- 글자 배치: “그림과 대사는 그대로 두고, 말풍선이 얼굴을 가리지 않게 옮겨 줘.”

바꾸는 범위에 따라 다시 검토할 단계가 달라집니다. 바뀌지 않은 컷은 그대로 쓰지만, 참조하는 앞
그림이나 구도가 바뀌면 관련 컷도 다시 봅니다. 다시 그릴 범위를 먼저 물어보면 불필요한 이미지
비용을 줄일 수 있습니다.

중간에 멈췄다면:

> 진행 중인 **웹툰** 작업을 확인하고, 남은 단계부터 이어서 해 줘. 새 작업을 만들지 마.

다음 회차를 시작하려면:

> 웹툰 1화 장면이 검토 완료(completed)인지 확인하고, 원작 2화로 웹툰 2화를 시작해. 기존 그림체와 참조 그림은 다시 써.

이미 끝낸 회차를 다시 각색하면 이전 결과를 남겨 둔 채 새 작업으로 만듭니다. 원작을 나중에
고쳐도 제작 중인 웹툰의 원작이 자동으로 바뀌지는 않습니다. 새 원작으로 다시 만들려면 그렇게
요청하세요.

문제가 생기면 [문제 해결과 백업](TROUBLESHOOTING.md)을, MCP를 직접 연동한다면
[웹툰 실행 규약](reference/WEBTOON_WORKFLOW.md)을 보세요.
