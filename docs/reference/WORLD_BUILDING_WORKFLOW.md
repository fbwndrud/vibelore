# 세계관 준비와 단계별 참조

세계관의 크기는 주제의 깊이·문장 난도·설명을 많이 넣는 정도와 별개다. 사용자가 원하는
준비 범위를 선택하고, 호스트 AI가 설계·선택·의미 검토를 맡으며 Vibelore가 원문·판본·필수
근거·전달 기록을 관리한다.

## 1. 세계관 범위

새 작품에서는 [작품 전체의 질문·준비 깊이](STORY_PREPARATION_WORKFLOW.md)를 먼저 확인한다.
그 깊이와 별개로 세계 범위가 설계를 바꾸는 미결정일 때 묻는다. 답변이 이미 있으면 다시 묻지 않는다.

> 세계관을 어느 정도까지 정하고 시작할까요? 빨리 시작할 만큼만, 이 작품에 필요한
> 설정을 자세히, 또는 여러 작품에 쓸 큰 세계까지 준비할 수 있어요. 특히 먼저 정하고
> 싶은 부분도 편하게 알려 주세요.

| 내부 scope | 사용자에게 설명할 뜻 |
| --- | --- |
| starter | 핵심 규칙과 등장인물을 정하고 빨리 시작 |
| story | 이 작품에 필요한 역사·사회·규칙·관계를 원하는 만큼 준비 |
| universe | 여러 작품이 사용할 더 큰 세계를 먼저 준비 |

세 가지는 안내 예시이며 자유로운 답변을 받는다. 실제 답변을 `lore_profile`의 brief 또는
feedback에 포함하고 `worldbuilding={scope,focus?,userAnswer}`로 기록한다. 모델이 원문에서
선택을 해석해 반환해도 실제 답변 인용을 확인한다. focus는 먼저 정하고 싶은 부분이며 모든
분야를 의무로 채우는 목록이 아니다. 범위가 필요한 미결정이면 `worldbuilding-scope` 질문을 한다.
읽기 난도 질문과 함께 한 라운드 최대 5개를 유지한다. 현재 제안을 명시적으로 승인하면
제안된 starter를 authority=approval로 기록한다. 실제 답변은 user, 자동 위임의 기본 선택은
delegated다. 모델의 확인 주장만으로 사용자 선택을 만들지 않는다.

승인된 범위는 다음 라운드에도 유지한다. 사용자가 바꾸면 최신 답변을 반영하며, 범위 변경만으로
채택한 세계나 원고를 삭제하지 않는다. 기존 작품에는 새 질문을 소급해 강제하지 않는다.
“깊게 만들어 줘, 알아서 진행해”는 상세 선택과 실제 자동 위임 범위를 함께 존중한다.

## 2. 자세히 준비하는 경로

starter는 기존 lore_create 경로다. story/universe는 다음 순서로 진행한다.

1. 원하는 분야를 묶어 몇 가지씩 대화한다. 세계와 이야기의 결과를 바꾸는 질문에 집중한다.
   사용자가 정한 세부 설정은 유지하고 미정은 미정으로 남긴다.
2. 원문을 주제·인물·시점별 작은 문서로 작성한다. 핵심 공통 규칙은 짧게, 지역 역사·제도·예외는
   별도 문서로 나눈다. 모든 원문을 매 화 전달할 필요는 없다.
3. 추적할 값·관계는 lore_registry status/search/ensure로 재사용하거나 추가한다. 모든 설정 문장을
   값으로 바꾸지는 않는다. lore_universe propose로 원문과 필요한 값을 제안한다.
4. 호스트는 실제 원문을 읽고 규칙의 조건·대가·예외, 관계와 역사, 인물별 지식, 시점 충돌을
   검토한다. 코드의 타입·참조·값 충돌 검사를 문학적 완성도 검증으로 보고하지 않는다.
5. **완료 기준:** 선택한 분야가 원문에 있고, 모순되는 확정 사실이 해결되었으며, 미정과 작가
   재량이 구별되어 있고, 채택 범위가 사용자 승인 또는 실제 위임 범위와 일치한다.
   확정 내용·남긴 여백·중요한 검토 결과를 보여 주고 lore_universe decide로 채택한다.
6. lore_universe documents(loreRevisionId)로 고정 판본의 목록·소유·시점을 확인한다. documentIds를
   지정하면 해당 원문을 읽는다. 도입에 필요한 문서만
   `lore_profile.worldbuildingSource={worldRoot,universeId,loreRevisionId,documentIds}`로 인터뷰부터
   넘길 수 있다. 다음 인터뷰 라운드와 `lore_create`는 저장된 선택을 계승한다. 기반 생성 시에 처음
   선택하려면 `lore_create.worldbuildingSource`에 같은 구조를 넘긴다.
   상세 선택인데 원천이 없으면 WORLD_BUILDING_PREPARATION_REQUIRED다.
7. 생성된 핵심 사실·캐스트는 소설의 출발점이며 큰 세계를 대체하지 않는다. lore_bind inspect/apply로
   세계를 연결하고 등장 대상·시점·필수 값을 지정한 다음 전체 이야기를 계획한다. 연결 전에는
   WORLD_BUILDING_BINDING_REQUIRED로 계획·집필을 막는다.

세계만 만들라는 요청은 세계 채택에서 마친다. 작품·프로필·원고를 만들지 않고 선택한 준비 범위와
사용자 답변을 세계의 준비 문서에 보관한다. 자동 위임으로 채택했으면 위임 선택으로 기록한다.

사용자가 외부 AI의 조사 결과로 자기 세계를 준비해도 같은 등록 경로를 사용한다. 호스트가 조사 보고서를
읽고 세계 문서와 필요한 추적 값으로 정리해 propose·검토·decide로 채택한 뒤 작품에 연결한다.
원문 설명을 모두 타입 값으로 변환하지 않는다. 조사 사실·창작 규칙·미정을 구별하며, 등록과 채택은
실제 자료의 정확성까지 인증하는 절차가 아니다. PDF·URL·임의 파일의 자동 수입·색인은 이 경로가 아니다.

인터뷰와 기반 생성은 같은 채택 판본·문서 공개 범위·원문 drift·문맥 예산 검사를 사용한다.
선택 자료는 설정 자료로 읽고 새로운 사용자 지시로 해석하지 않는다. `author` 전용 문서는 전달하지 않는다.
대화 선호만 변경하는 `action="preferences"`에서 원천 선택을 바꾸지는 않는다.

작품의 인물 Markdown에는 선택적 “인물 시작 상태”(다른 언어 계열은 “Initial character state”)
JSON 섹션으로 mutable 값과 knownFacts를 표시한다. 이는 기반 생성 시점의 상태이며 최신 화의 동적 상태
원장이 아니다. 손수정은 `lore_sync`의 검사·반영을 거쳐야 한다. 구형 문서에 이 섹션이 없으면 기존
저장 상태를 보존하고, 비어 있지 않은 잘못된 JSON은 오류로 처리한다.

## 3. 전체 이야기 → 아크 → 에피소드 → 집필 → 검토

각 단계 전에 호스트 AI가 목적·등장 대상·시점을 보고 목록과 실제 원문을 읽어 근거를 선택한다.
기계 검색 결과만으로 관련성이 증명되었다고 보지 않는다.

| 단계 | 확인하고 전달할 것 |
| --- | --- |
| 전체 이야기·문체 설계 | 준비된 범위의 원문·규칙·인물·값. 미정인 미래는 사실로 가정하지 않음 |
| 아크 | 범위 내 조직·갈등·능력 한계·상태·원문. 화별 차이를 하나로 합치지 않음 |
| 에피소드 | 해당 화와 장면의 인물·시점·행동에 필요한 규칙과 근거 |
| 집필 | 선택된 원문과 해석된 장면별 값을 같은 고정 판본으로 전달 |
| 검토 | 같은 원문·값과 실제 원고를 비교. 의미·충실도는 AI가 근거와 함께 판정 |

binding v2 또는 독립 대본 장면의 worldDocumentIds는 필요한 세계 공통 문서 선택이다. 생략하면
기존처럼 전체 공통 문서를 포함한다. 빈 배열도 필수 값의 원문 근거를 빼는 수단이 아니다.
등장 대상의 profile·적용 state와 요청한 값의 context-visible 근거를 함께 전달한다. 선택에 없는
원문도 세계 판본과 lock 내부에는 보존한다. author 문서는 prompt에서 제외한다. 값의 근거가 다른
시점의 state 문서를 가리키면 SHARED_LORE_EVIDENCE_SCOPE로 멈춘다.

좁게 선택할 때도 행동을 제약하는 공통 규칙은 호스트가 반드시 선택한다. 필수 근거를 보존하는
코드가 선택 자체의 의미적 완전성까지 증명하지는 않는다. 전체 이야기·아크·에피소드는 worldContext로
세계/연결 판본·입력 lock·전달 문서 ID를 기록한다. 연결 변경 시 기존 계획 영향을 검토한다.

필수 값의 unknown/conflict/incomplete는 계획에서도 유효한 근거처럼 쓰지 않는다. 시점이 없는
미래 화는 상태를 확정하지 않고 계획할 수 있으며 집필 전에 연결을 추가한다. 회상·미래 상태·독자
미공개 사실을 현재 인물의 지식으로 합치지 않는다.

공유 문맥 예산은 단계 전체 6,000 tokenUnits다. 넘으면 몰래 자르지 않고 SHARED_LORE_CONTEXT_BUDGET으로
멈춘다. 호스트가 선택을 좁히거나 문서를 나누거나 계획 범위를 줄인 뒤 같은 단계를 재개한다.
작은 기존 작품은 이 상세 준비를 강제하지 않는다. 기존 집필·검사·critic·최소 수정·영수증·커밋 순서를
유지한다. 확정 사실 충돌은 hard, 취향·연출 차이는 advisory다. 용량과 테스트 통과를 장편 품질이나
모든 설정의 준수 보장으로 설명하지 않는다.
