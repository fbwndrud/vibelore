# 작품 준비와 단계별 검토·재작성

작가의 집필 경험을 제품에 적용한 실행 규약이다. 최적 질문 수나 AI 검토 성능을 입증한 결과는 아니다.

## 먼저 대화의 깊이를 정한다

새 작품에서 다른 설계 질문을 하기 전에 한 번 묻는다. 이미 원문에 답이 있으면 재질문하지 않는다.

> 이야기를 쓰기 전에 얼마나 함께 묻고 정하면 좋을까요? 꼭 필요한 것만 정하고 시작해도 되고,
> 중요한 선택들을 함께 정해도 되고, 세계관·인물·이야기·문체까지 충분히 살펴봐도 돼요.
> 특히 깊게 다루고 싶은 부분이 있으면 알려 주세요.

이는 작품 전체의 **협업·준비 깊이**다. 세계의 크기, 문장의 난도, 작품의 완성도와 별개다.
자유로운 답변을 호스트가 해석하고 원문 전체를 brief/feedback에 보존한다.
`lore_profile.discovery={depth:quick|standard|deep,focus?,userAnswer}`는 그 해석과 실제 인용이다.
focus가 있으면 그 부분을 깊게 탐색하고 다른 분야는 시작에 필요한 정도로 둔다.
“인물은 자세히, 세계는 쓰면서”는 인물을 중심으로 준비한다는 뜻이며 큰 공유 세계 선택이 아니다.
“질문은 적게, 세계는 크게”도 가능하다. 세계 범위는 실제 설계상 필요한 시점에 별도로 확인한다.

- quick: 중요한 갈림길만 한 라운드 최대 3개 묻고, 나머지는 제안과 열린 여백으로 정리한다.
- standard: 중요한 선택을 함께 정한다. 한 라운드 최대 5개이며 필요한 답이 있으면 일찍 끝낸다.
- deep: 원하는 영역의 조건·관계·예외와 작품에 미치는 영향을 충분히 탐색한다. 같은 질문 수 제한을
  지키며 관련된 미결정이 해결될 때까지 이어간다. 이름·소품·불필요한 속성을 모두 채우는 목표가 아니다.

첫 선택이 미정인 review는 `discovery-depth` 질문 하나만 노출한다. 이때 프로필은 잠정 후보이며
승인할 수 없다. 답을 기록해 다음 review를 이어간다. 첫 질문에 자동 권장값을 승인으로 보고하지 않는다.
“알아서/묻지 말고”는 기존 auto 경로로 질문을 생략하며 기본 quick 선택을 delegated로 기록한다.
이미 있는 상세 선택은 위임했다고 지우지 않는다. 기존 프로필에는 새 첫 질문을 소급해 강제하지 않는다.

진행 중 답이 바뀌면 최신 원문으로 갱신한다. 활성 프로필의 대화 선호만 바꿀 때는
`lore_profile(action="preferences",brief="",feedback="실제 변경 답변",discovery={...})`를 쓴다.
작품을 다시 생성하지 않고 active 상태와 작품 내용은 보존한다. 새 선호의 승인 언어 영수증은 갱신한다.
내용 자체를 바꾸려는 요청이면 기존 design/review 경로에서 관련 계획 영향을 확인한다.

## 각 단계의 만들기 → 읽기 → 필요한 수정 → 다시 읽기

상위 계획은 큰 방향과 필요한 여백, 가까운 구간은 더 구체적으로 준비한다. 작성 중 조사나 시험 장면으로
새로 알게 된 사실은 상위 설계로 돌아갈 이유가 될 수 있다. 아래 관점은 작품 목적에 맞춰 적용하며
모든 작품에 성장·반전·대가·클리프행어를 강제하지 않는다.

| 단계 | 집중해서 확인할 것 | 수정할 곳 |
| --- | --- | --- |
| 작품 방향·세계·인물·문체 | 사용자 의도, 미정과 확정의 구분, 규칙과 관계가 장면에서 작동하는지 | profile feedback / 세계 제안·검토·채택 / 문체 audition. 필요하면 시험 장면으로 확인 |
| 전체 이야기 | 독자 약속, 인물의 선택, 사건 인과, 시작·끝의 변화, 세계 조건의 결과 | lore_story_plan feedback으로 같은 단계 재작성. 시작점·시점·조사 결과도 고려 |
| 아크 | 상위 약속, 압력과 회수, 인물별 목적, 시점별 상태·지식, 다음 구간에 남는 결과 | lore_arc_plan feedback. 상위 약속 변경은 전체 이야기부터 영향 확인 |
| 에피소드 | 전체 이야기 약속과 아크의 역할, 시작과 끝의 변화, 목표·장애·선택, 장면 인과, 시점과 설명, 보상과 다음 질문 | lore_episode_plan feedback. lore_write의 내부 계획에도 같은 검토 적용 |
| 실제 원고 | 계획의 실제 반영, 혼란·불신·지루함·흥미의 구체적 위치, 인물의 목소리 | 기존 lore_write 검사·critic·최소 수정·재검사; 사용자 수정은 lore_decide request_revision |
| 완성 구간·전체 | 연속해서 읽는 구조·페이싱·정보 공개·관계; 안정된 구조에서 문장과 리듬 | lore_arc_review scope=range로 정본 전체 읽기. 이전 화 변경은 재검사·재커밋·refold |

호스트는 각 실제 결과와 같은 판본의 설정·상위 약속·사용자 요구를 읽는다. 결과가 길거나 항목이 많다는
이유로 충실함을 판정하지 않는다. 검토에는 잘 작동한 부분도 보존 근거로 남긴다. 수정에는 추가·구체화뿐
아니라 삭제·압축·순서 변경·자료 조사·다른 시점·상위 설계로 돌아가기·보류가 있다.

새 discovery 프로필의 전체 이야기·아크·에피소드는 켜 둔 단계별 모델 검토를 실행한다. 각 focus에 실제 후보의
구체적 근거와 met/gap/not_applicable을 남긴다. 확정 요구 위반만 실제 요구 인용과 수정 지시를 붙여 repair로
처리하며 한 번 수정 후 실제 수정본을 다시 읽는다. 구조·분량·기존 품질·언어 검사는 수정본에도 적용한다.
advisory인 취향과 풍부해질 기회는 자동 수정하지 않는다. 상위 변경은 upstream, 필요한 추가 조사는 research로
보고하고 하위 자동 수정을 멈춘다. 실패 후보는 활성 계획을 덮어쓰지 않으며 근거와 후보를 돌려준다.
호스트는 해당 단계의 feedback으로 수정하거나 상위 단계·조사를 진행해 다시 호출한다.

stageReview는 사용한 프로필 revision·준비 선호·문맥 hash·검토한 후보별 hash와 검토 근거를 기록한다.
검토의 independence는 not-established다. 같은 호스트의 다른 호출은 실제 독자나 독립 작가 검증이 아니다.
자동 수정 1회는 실행 비용 한도이며 작가 경험에서 입증한 최적 횟수가 아니다. 기존 discovery 없는/legacy
프로필의 실행 경로는 유지하며 사용자가 planningReviews의 단계를 true로 켜면 의미 검토를 적용한다.
에피소드 생성과 검토에 승인된 StorySpine을 직접 전달하며, 전체 약속과 아크 약속을 각각 확인한다.

검토에는 전체 문맥과 별도로 `authority`를 전달한다. 사용자 브리프·방향·피드백, 채택 사실과 상위
작품 약속이 필수 수정의 근거다. 모델이 만든 promptGuidance·문체 기법·이전 검토 의견은 보조 문맥이며
그것만 인용해 필수 수정을 요구할 수 없다. 사용자가 브리프에서 같은 기법을 직접 요구했다면 그 원문은
권한 근거가 된다. 인용은 한 원문 필드 안의 실제 연속 문자열이어야 하며 서로 다른 문장을 이어 붙이지 않는다.

검토 JSON·필수 관점·인용 형식이 잘못되면 같은 후보로 `*-plan-review-response-repair`를 한 번 요청한다.
이는 계획 재작성 횟수와 별개다. 응답을 다시 검증하고 재실패하면 중단한다. `upstream`·`research`는
`*-plan-escalation-review`에서 상위 요구와 후보를 다시 비교한다. 필요한 복귀인지, 하위 수정으로
충족할 수 있는지, 모호한 표현이나 취향인지 구별하고 실제 근거를 남긴다. “고백한 뒤 동행한다”가 같은
회차를 명시하지 않았다면 회차가 다르다는 이유만으로 상위 변경을 강제하지 않는다. 실제 상위 설정끼리
충돌하면 하위 계획으로 감추지 않고 복귀한다. 두 추가 모델 요청은 필요할 때만 발생한다.

기반 자동 생성에서 유효한 언어 fail이 오면 같은 후보를 반복 검사하지 않는다. 지적된 생성 문구 중
허용된 필드만 한 번 번역하고, 실제 의미 비교와 새 후보 hash의 언어 검사를 모두 통과해야 저장한다.
ID·기계 값·채택 이름·원문 자료는 교정 대상이 아니다. 의미 변화·허용 밖 패치·재실패는 중단한다.
수동 초기화와 기존 승인 결과에는 이 자동 교정을 적용하지 않는다. 원래 실패와 교정 영수증을 별도로 남긴다.

시스템의 전체 이야기·문체 계획 Markdown 저장은 해당 파일의 fingerprint만 갱신한다. 다른 정본의
손수정은 계속 drift로 보고하고, 계획 파일 자체가 손수정되었으면 덮어쓰지 않고 `lore_sync`를 요구한다.

## 검토 항목과 빈도의 선택

대화의 준비 깊이는 얼마나 묻고 준비할지다. 검토 선택은 실제 결과를 어느 단계와 빈도로 살펴볼지다.
두 선택을 서로 추정해 덮어쓰지 않는다. 검토 선택이 필요한 때 사용자에게 다음처럼 설명한다.

> 쓰면서 매번 자세히 점검할까요, 큰 구간이 끝날 때 집중해서 볼까요? 특히 확인하고 싶은 부분이나
> 빼고 싶은 점검이 있으면 편하게 말해 주세요.

기존 선택을 다시 묻지 않고, 별도 요구가 없으면 기본 검토를 유지한다. “알아서”는 현재 검토 선택을
보존하며 선택이 없으면 기본값을 쓴다. 질문을 적게 하겠다는 답을 검토를 끄라는 지시로 해석하지 않는다.
기본 검토 변경 전에 사용자의 말에서 어떤 항목과 빈도를 원하는지 정리한다.

- `lore_configure(planningReviews={story,arc,episode})`: 지정한 단계만 갱신한다. false는 단계의
  의미·품질 모델 검토를 모두 생략하고 disabled_by_user로 남긴다. true는 켠다. 선택은 이후 실행에 적용한다.
- `disabledReviews`: 원고 검토 중 끌 목록 전체다. 기존 6개 항목과 `arc-review`를 선택할 수 있다.
  기존 목록을 먼저 확인해 새 선택 때문에 다른 꺼진 검토를 되살리지 않는다. 빈 배열은 모두 켠다.
- `arcReview={everyEpisodes,atEnd}`: 자동 누적 검토 시점이다. 기본 5화마다와 종료 시점이며
  everyEpisodes=0은 중간 검토 생략, atEnd=false는 종료 검토 생략이다. 지정한 필드만 갱신한다.

검토 선택의 변경은 reviewRevision과 변경 전·후 값, 변경 시점·다음 화 번호를 기록한다. 조회와 동일한
선택의 재저장은 새 변경으로 만들지 않는다. 단계 검토 기록은 적용한 reviewPolicyRevision도 남긴다.

구조·필수 참조·설정 값·문맥 예산·언어·커밋 영수증 검사는 검토 선택으로 해제되지 않는다.
꺼진 모델 검토는 실패가 아니며 auto를 막지 않는다. 켠 critic이 실제로 실패하면 기존 guided 강등을 따른다.
creative advisory를 설정의 hard 위반으로 승격하지 않는다. 모든 단계 쌍을 별도 모델 작업으로 만들지 않고
각 단계에서 결과 자체·상위 약속·관련 설정을 함께 본다.

## 완성 구간을 실제 원고로 읽기

기존 `lore_arc_review(scope="arc")`는 요약과 최근 원고로 누적 흐름을 점검하는 체크포인트 검토다.
전체 구간을 읽고 싶으면 `scope="range",fromChapter=시작,throughChapter=끝,focus="관심 사항"`을 쓴다.
전체 작품도 1화부터 마지막 정본 화까지 범위를 지정해 같은 경로로 검토한다. 자동 검토를 껐어도 명시적
수동 요청은 실행한다. range는 PatternLedger를 새로 만들지 않는다.

range는 공개 정본 HEAD를 기준으로 모든 원고 조각을 전달한다. 화 안에서도 긴 본문을 나누며 원문을
빠뜨리지 않는다. 조각마다 실제 인용을 확인하고 긴 읽기 기록은 묶음별로 종합한 뒤 전체 약속·누적 인과·
인물·세계·페이싱과 회수를 검토한다. 부분 구간에서 미래 결말을 아직 회수하지 않은 것은 실패가 아니다.
비교 설계는 현재 승인된 전체 이야기·아크이며 과거 집필 당시 설계로 가장하지 않는다. 화별 봉인 세계
입력이 있으면 그 판본을 사용한다. 정본이 실행 중 바뀌면 성공 기록 대신 새 HEAD로 다시 검토하도록 멈춘다.

정본 HEAD, 원고 hash, 화·조각별 전달 범위, 실제 인용과 읽기 기록, 종합 근거를 저장한다. 응답에는
결론·인용 근거·읽은 범위와 전체 보고서 경로를 돌려줘 긴 읽기 기록으로 MCP 응답을 채우지 않는다.
`lore_arc_review(scope="range",action="status",reviewId=...)`로 조회하며 ID 생략은 최신 결과다.
정본 HEAD나 승인 설계가 바뀐 뒤 이전 검토를 조회하면 freshness=stale로 표시하고 과거 근거는 보존한다.
결과는 advisory이며 정본 자동 재작성·커밋을 하지 않는다. 수정은 기존 승인·검사·영향 검토 경로로 진행한다.
분할 읽기와 근거 확인은 의미 판단의 정확성이나 독립 독자 평가를 증명하지 않는다.

## 세계를 나누어 볼 때

세계 특성은 고정 장르표가 아니라 필요한 조사와 검토를 고르는 관점이다. 섞여 있을 수 있다.

- 현실·역사·직업·생활: 장면에 필요한 시대·제도·가능한 행동을 실제 자료로 확인하고 출처·불확실성을 남긴다.
- 만든 사회·마법·물리·기술: 조건·한계·예외가 행동과 결과에 영향을 주는지 본다. 필요하면 짧은 장면으로 확인한다.
- 공유 세계: 작품 간 하나의 연속 역사를 공유하는지, 느슨한 연결이나 다른 연속성을 허용하는지 별도로 정한다.
- 연재: 독립 회차와 연속 구간의 읽기 경험, 공개 속도와 수정 여유를 구분한다. 독자 의견은 사용자 지시와 별개다.

상세 세계의 정리·채택·원문 선택·판본·시점 관리는 [세계관 준비 흐름](WORLD_BUILDING_WORKFLOW.md)을 따른다.
호스트 AI는 해석·선택·의미 검토를, Vibelore는 실제 원문·판본·필수 근거·검토와 변경 기록을 맡는다.
코드는 인용과 참조를 확인하지만 문학적 적합성이나 모든 문서 선택의 충분함을 증명하지 않는다.
