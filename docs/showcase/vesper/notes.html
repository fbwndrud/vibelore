PRODUCTION NOTES · VIBELORE 0.4.2

제작 노트

50화를 어떻게 완결했고 무엇이 틀렸는지 적었습니다. 수치는 실행 기록(모델 호출 로그, vibelore 워크플로 기록)에서 읽은 값입니다.

만든 순서

  1. 작품 발견 인터뷰. 롯데월드 야간 퍼레이드의 가로등 신사 베스퍼와 촛불 머리 칸드라를 빌린 실명 팬 창작으로 정했습니다. 사용자와 인터뷰해 인외 로맨틱 코미디, 정체 은폐, 11월 15일 문이 닫히는 시한, 달콤한 해피엔딩을 독서 계약(StoryProfile)에 담았습니다. 실존 공연자·직원을 특정하지 않고, 로고를 쓰지 않으며, 상업적으로 쓰지 않는다는 조건도 함께 정했습니다.
  2. 설계. 작품 생성, 이야기 뼈대(StorySpine), 작가 스킬, 아크 설계의 모델 응답은 모두 Claude Opus 5.5가 냈습니다. 요청마다 새 claude -p 프로세스를 띄우고(effort high, 도구 없음, 프롬프트 캐시 끔) 앞 요청의 맥락을 넘기지 않았습니다.
  3. 7개 아크, 50화. 아크를 하나 승인할 때마다 lore_write 자동 모드로 화별 계획 → 초고 → 결정론 검사 → critic 검토 → 필요한 최소 수정 → 커밋을 돌렸습니다. 50화 모두 자동 커밋됐습니다. 중간에 멈춘 워크플로 4개는 서버를 고치거나 집필 지시를 보강한 뒤 다시 시작했습니다.
  4. 웹툰 인터뷰. 사용자가 로판 코미디 컬러 화풍, 칸 수 auto, gpt-image-2.5-sunburst, AI로 만든 기준 이미지를 골랐습니다.
  5. 장면 웹툰 1화. 호스트가 1화를 9장면으로 나누고, 장면마다 각색 → 사전 검증 → 이미지 API → 실제 이미지 검토를 돌렸습니다. 떨어진 장면은 서버가 결함 목록으로 다시 설계해 새로 그렸습니다(자동 재설계 최대 2회).

vibelore 버전

이 작품은 0.4.1에서 쓰기 시작했습니다. 쓰는 동안 드러난 아크 버그를 그때그때 고쳐 가며 이어 썼고, 그 수정은 모두 0.4.2 릴리스에 들어갔습니다. 웹툰은 0.4.2 릴리스로 만들었습니다. 아래 표는 워크플로 기록에 남은 실행 커밋입니다.

아크

아크 심사는 아크 중간과 끝에 vibelore가 요청하는 0~100점 검토입니다. 같은 모델이 매긴 점수라 독립 평가가 아닙니다.

집필 중 고친 vibelore 버그

  • 기계용 값을 문장으로 오판. 인물 생존 상태(vitalStatus)와 아크 증명 상태(proofStatus) 같은 열거값을 언어 검사가 한국어 문장으로 보고 영어라며 막았습니다. 기계용 값으로 분류하도록 고쳤습니다.
  • 장식용 인용 하나로 뒤집힌 통과. 연속성 검사가 통과 판정에 붙은 장식적인 인용 하나를 근거 오류로 보고 판정을 뒤집었습니다. 통과 판정은 그대로 두도록 고쳤습니다.
  • 개인 아크 동시 진행 한도. 한 번에 진행하는 인물 개인 아크는 둘까지입니다. 이 한도를 커밋 때에야 검사해 다 쓴 화가 버려졌습니다. 아크를 설계할 때 먼저 검사하고, 한도를 넘은 시작은 커밋을 막지 않고 빼도록 바꿨습니다.
  • 인물 아크가 처음 단계로 되돌아감. 20화에서 다온의 아크가 이미 지난 ‘시도’에서 ‘상처’로 되돌아가 커밋이 막혔습니다. 다음 아크를 설계할 때 인물의 마지막 단계를 커밋된 커서에서 읽어 넘기고, 이미 지난 단계는 건너뛰게 고쳤습니다. 앞 단계를 건너뛰는 것은 여전히 막습니다.
  • 아크 설계 규칙 명시. 3~7아크의 첫 설계안이 한도를 넘기거나 진행 중인 인물을 처음부터 다시 시작했습니다. 아크 설계 프롬프트에 한도와 이어 쓰기 규칙을 적었습니다.

모두 PR #9로 합쳐 0.4.2에 들어갔습니다.

기준 이미지

장면을 만들 때 이미지 모델에 함께 보낸 참조입니다. 공식 캐릭터 이미지를 쓰지 않고 글 설명만으로 새로 그렸습니다.

웹툰 1화 장면별 결과

반복된 결함

  • 겹받침 글자. 이미지 모델이 ‘앉혔다’를 ‘않혔다’로, ‘얹었다’를 ‘없었다’로, ‘너머’를 ‘너마’로 그렸습니다. 4장면은 네 번, 8장면은 세 번 그렸지만 같은 단어를 매번 틀렸습니다. 캡션을 나누고 해당 문구를 강조하는 수정도 소용이 없었습니다. 그래서 그림은 그대로 두고, 틀린 캡션 상자만 흰 바탕에 원문대로 다시 식자했습니다. 식자 전 원본과 서버 판정(수정 필요)은 리더에 함께 공개합니다.
  • 인외 디자인. 2장면 첫 시도에서 칸드라의 초에 불꽃이 둘 붙었습니다. 다시 설계해 그린 그림은 통과했습니다. 원문에 없는 얼굴 표정(불꽃 속 눈·입, 초의 홍조)은 참고 결함으로만 남겼습니다.
  • 잘된 점. 가스등 머리와 촛불 머리 두 인외, 퍼레이드 조명, 천막 뒤 공간이 9장면 내내 일관됐습니다. 대사와 자막 114줄 가운데 식자 전 기준으로 111줄이 원문과 글자 하나까지 같았습니다.

토큰과 비용

Claude 비용은 Claude Code CLI가 호출마다 보고한 API 환산 금액의 합입니다. 이미지 API는 호출별 요금을 돌려주지 않아, 같은 모델·품질의 장당 평균(이전 작품에서 OpenAI 사용량 API로 잰 값)을 곱한 추정값을 적었습니다.

밝혀 둘 한계

  • critic 검토와 그림 검토는 같은 Claude Opus 5.5가 했습니다. 요청마다 새 프로세스로 분리했지만 독립 독자 평가는 아닙니다.
  • 자동 모드에서 soft 판정과 critic 참고 의견은 커밋을 막지 않습니다. 28·31·40·46화에 남은 참고 의견은 아직 손보지 않았습니다.
  • 37화는 퍼레이드 출발 시각(저녁 7시로 적음)과 등갓의 금(새로 생긴 것처럼 적음)이 세계 정본과 달라 검사에서 막혔습니다. 두 사실을 집필 지시에 적고 다시 썼습니다.
  • 웹툰은 1화만 만들었습니다. 4·8장면의 캡션 후반 식자는 vibelore 밖에서 한 수정이라, 서버 기록에는 수정 필요로 남아 있습니다.
