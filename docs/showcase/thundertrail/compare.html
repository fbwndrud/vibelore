칸을 누르면 해당 장면으로 이동 · 색은 오케스트레이션 호스트의 실제 이미지 검토 판정

결함은 누구 책임인가

차단 판정 근거를 층위별로 나눴습니다. 이미지 모델은 네 회차 동일하므로 그 몫은 호스트 비교에서 빼고 읽어야 합니다.
이미지 모델 · 한글 한 글자 변형네→내, 번→변, 승→송, 표식→표석, 이어져→이여져, 표시→표저, 리아→리야(4화 s4). 네 회차 공통. 각색 호스트 잘못 아님.
이미지 모델 · 말풍선 화자 오귀속1화 s1·s3·s6, 4화 s2·s6. 브리프는 화자를 지정했으나 꼬리가 다른 인물에 붙음.
이미지 모델 · 계획에 없는 효과음1화 s4 ‘끼잉!’, s6 ‘흘쩍’, 2화 s3 ‘훗!’, 3화 s5 ‘콰르르’. 지정 문구 외 렌더링.
이미지 모델 · 칸 수 초과2화 s7(7/6), 3화 s2(6/5). 행이 둘로 갈라짐.
파이프라인 · 참조·지시 유도3화 s1·s3·s6·s7·s8 성곽 도시·창고: 지시문의 “밤→새벽 샛길→초소” 문구와 옆길 참조 이미지 속 먼 성곽 도시가 유도. s4부터 지시문 교체.
이미지 모델 · 잃은 소품 복원4화 s1·s2·s6 도윤 허리·손의 밧줄. 3화에서 잃어 원문은 빈 고리뿐인데 세 장면에서 되살아남.
이미지 모델 · 손·자세 창작4화 s4·s5 펜이 리아 오른손(원문은 접힌 손목, 왼손 글씨), s5 보리가 바닥에 내려옴, s6 모자 바로잡는 사람이 도윤 복장.
이미지 모델 · 계획에 없는 글자4화 s4 장부의 표·이름, s7 장부의 창작 문장·쪽지의 두 이름. 지정 문구 외 한글 렌더.
각색 호스트 · 계획 오류2화 s8 마차·인부(계획이 “마차 여부 미지정”으로 열어 둠), 3화 s8 손바닥 자국(“같은 손”을 handprint로 오독).

직접 해보기

같은 파이프라인을 원하는 호스트로 돌릴 수 있습니다. 소설은 lore_write, 웹툰은 lore_webtoon_scene 하나로 시작합니다.
1. vibelore MCP 서버 연결호스트 CLI(Codex / Claude Code / Grok)에 stdio MCP로 등록합니다.
git clone https://github.com/fbwndrud/vibelore
cd vibelore && npm install
# 호스트별 등록은 docs/HOSTS.md 참고
claude mcp add vibelore -- node src/server.js
2. 소설 한 회차회차 계획 → 초고 → 의미·논리 검사 → 최대 3회 수정 → 승인. 호스트가 바뀌어도 순서는 같습니다.
lore_write { workId, chapter: 1 }
# needs_model 이 오면 lore_resume 으로 답변
3. 장면 웹툰 한 장면원문 단락 범위를 주면 각색 → 사전 검증 → 이미지 1회 → 시각 검토. 칸 수 auto = 3~12칸.
lore_webtoon_scene {
  action: "start", workId, sourceChapters: [1],
  sourceUnitIds: ["ch-1-p-1", …], panelCount: "auto",
  direction: "…(영어)…", references: […] }
이 페이지의 모든 수치는 data.json에서 그대로 읽습니다. 빌드 .
