vibelore는 이렇게 동작합니다

vibelore는 글이나 그림을 직접 만들지 않습니다. 연결한 AI가 쓰고 그리며, vibelore는 그 사이에서 순서와 검사, 승인과 저장을 지킵니다. 사용자는 채팅창에서 요청하고 결과를 확인하면 됩니다.

사용자요청하고 고르고 승인

취향과 각색 범위, 이미지 모델과 과금 경로를 고르고 결과를 확인합니다.

도구 호출 순서나 내부 ID는 몰라도 됩니다.
채팅
요청 · 승인
연결한 AI · 호스트쓰고, 그리고, 읽는다

계획·원고·검토 응답을 쓰고, 이미지 API를 호출하고, 실제 그림을 열어 봅니다. Claude, GPT, Codex 등.

사용자 동의 없이 모델·과금 경로를 바꾸지 않습니다.

스스로 글·그림을 만들지 않고, 모든 의미 오류를 판정하지도 않습니다.

한 번의 왕복

  1. 1“다음 화 써 줘”사용자가 채팅으로 요청
  2. 2lore_write호스트가 vibelore 도구를 부름
  3. 3needs_model서버가 답해야 할 요청 묶음을 돌려줌. 서로 독립이면 한 번에
  4. 4병렬로 답하기호스트가 요청마다 원고와 근거를 읽고 답함
  5. 5lore_resume모든 답을 한 번에 넘김. 서버가 검사하고 다음 단계로
  6. 6승인 또는 반복끝나면 사용자에게 결과, 아니면 3으로

작업 단계와 대기 요청은 로컬에 저장됩니다. 앱이 꺼져도 다시 연결하면 멈춘 곳부터 이어갑니다.

소설 레인 작품 → 아크 → 화

작품 설계를 한 번 승인하고, 3~20화 아크를 승인받고, 한 화씩 계획·초고·검사·수정·커밋. 한 화가 하나의 영속 워크플로입니다.

소설 한 화 흐름 보기 → 웹툰 레인 · 소설과 따로 원작 문단 → 장면 한 장

고정한 원작 판본을 복사해 각색하고, 그리기 전에 검증하고, 그린 뒤 실제 그림을 검토합니다. 웹툰은 소설 정본을 덮어쓰지 않습니다.
