AI사람

아크의 약속과 화별 사건·압력·전환·다음 상태. 활성 아크가 있어야 화를 씁니다.

화마다 · lore_write 하나아래 일곱 단계를 한 워크플로로

시작할 때 손으로 고친 정본이 있는지 먼저 봅니다. 있으면 동기화부터. 중간에 끊겨도 같은 자리에서 이어갑니다.

  1. 1
    이번 화 계획AI코드

    아크의 이번 화 비트를 2~4개 장면, 인물의 선택, 독자가 예상할 것과 실제 전환으로 풀어 씁니다. 코드가 필수 항목, 등장인물 ID, 집필 묶음 예산(4,000토큰)을 확인하고, 어긋나면 한 번 고쳐 받습니다.

    받는 것 아크 비트 · 직전 화 요약 · 열린 떡밥 → 내놓는 것 화별 계획
  2. 2
    초고AI

    계획을 압축한 집필 묶음에, 이번 화에 나오는 인물과 세계 설정·불변식, 이야기 등록부의 현재 값과 긴 기억, 직전 화 끝 2,400자, 문체 기준을 붙여 한 화를 씁니다.

    일부 입력(오래된 기억·직전 화 끝·작가 기법·문체 기준)은 작품별로 뺄 수 있습니다.
  3. 3
    검사와 검토서로 기다리지 않는 요청은 한 왕복에 묶어 병렬로
    코드규칙 검사분량·형식·계획 이행을 모델 없이 판정. 추출이 끝나면 이야기 등록부와의 충돌도.
    AI상태 추출 → 의미 연속성위치·부상·소지품·알게 된 사실을 뽑고, 다음 왕복에서 정본과 뜻이 맞는지 검사.
    AI비평가 6종프로필 이탈·논리·장면의 힘·인물·독자 훅·반복. 추출과 같은 왕복. 작품별로 끌 수 있습니다.
    AI아크 검토아크의 5화마다와 마지막 화에만. 앞 화들과 이어 읽습니다.
    작품 언어와 원고 언어가 다르면 막는 언어 검사도 같이 돌아갑니다.
  4. 4
    판정코드

    막는 것은 확정 사실과의 충돌(hard), 분량 미달, 웹소설 줄바꿈 형식 셋입니다. 의미 검사가 원문을 근거로 실패하면 hard가 됩니다. 나머지 soft 위반과 비평가 의견은 기록만 하고 작가 판단에 남깁니다.

    막히면 최소 수정 → 3으로 다시 검사원고를 다시 쓰지 않고 걸린 곳만 고칩니다. 검사 실패는 세 번까지, 수정은 앞의 두 번 실패 뒤에만. 바뀌지 않은 문단이 75% 이상이어야 하고(분량 수정 65%, 형식 수정 50%) 못 지키면 멈춥니다.
  5. 5
    통과 → 제목·요약·다음 화 판단, 영수증AI코드

    통과한 원고만 읽고 제목과 요약, 아크를 계속할지 닫을지의 판단을 만듭니다. 서버는 통과한 원고의 해시로 검사 영수증을 발급합니다.

  6. 6
    저장 방식 · 두 가지
    guided · 기본사람
    원고와 검토 의견을 보여 주고 사용자가 승인, 수정 요청, 보류, 거절 중에서 고릅니다.
    auto코드
    켜 둔 검토가 모두 끝나고 문체 이탈이 없을 때만 자동 저장. 아니면 guided로 내려갑니다.
  7. 7
    커밋코드

    영수증의 해시와 통과 판정이 저장할 원고와 같은지 다시 확인한 뒤 정본에 씁니다. 이야기 등록부·요약·스냅샷을 갱신하고, 5에서 정한 다음 화 판단을 적용합니다.

    내놓는 것 chapters/ 원고 · 검사 영수증 · 이야기 등록부 · 복구용 스냅샷
    다음 화는 1로. 아크가 끝났으면 새 아크를 승인받고, 끝난 아크의 요약은 다음 화를 시작할 때 긴 기억으로 만듭니다.

이야기 등록부물건·지식·예정 사건·떡밥의 현재 값과 최근 3화 사건

화가 늘어도 입력은 크게 늘지 않습니다. 전체 이력 대신 현재 값을 넘기고, 20화 넘게 쉬던 기록이 돌아오면 이력을 최대 5줄 붙입니다.
