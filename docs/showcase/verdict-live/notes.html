PRODUCTION NOTES

제작 노트

어떻게 만들었고, 무엇이 틀렸는지. 수치는 CLI·API 실행 기록에서 읽은 값입니다. 검토 판정은 제작에 쓴 모델의 자기검토이며 독립 평가가 아닙니다.

만든 순서

  1. 작품 설계. 사용자가 후보 다섯 중 고른 설정(렉카 주인공, 1화 동생 해명 방송, 99% 정지, 동생의 합성 알바 과거)을 인터뷰로 확정하고, 독서 계약·세계·인물·이야기 뼈대(StorySpine)를 만들었습니다.
  2. 소설 1~3화. 5화 아크를 세운 뒤 lore_write 자동 모드로 화별 계획 → 초고 → 결정론 검사 → 비평 → 필요한 최소 수정 → 커밋을 돌렸습니다.
  3. 웹툰 인터뷰. 작화(모던 스릴러 컬러)·문자(standard)·판면(세로 스크롤)·경로(장면 통합, 칸 수 auto)는 사용자가 골랐고, 나머지는 사용자 위임(“웹툰 나머지 알아서”)으로 권장안을 적용했습니다. “현대적이고 세련된 연출”은 사용자 요청으로 추가했습니다.
  4. 기준 이미지. 인물 셋과 장소 셋의 기준 이미지를 같은 이미지 모델로 먼저 만들고, 모든 장면에 참조로 붙였습니다.
  5. 장면 웹툰. 화마다 원문을 8장면으로 나누고, 장면마다 각색(사실·비트·대사 선택) → 사전 검증(그릴 수 있는지, 원문과 맞는지) → 이미지 API 한 번(칸 수는 각색이 3~12 중 결정) → 실제 이미지 검토 순으로 진행했습니다. 앞 장면의 완성 이미지를 다음 장면의 참조로 넘깁니다.

기준 이미지

장면 생성 때 이미지 모델에 함께 보낸 참조입니다. 편의점 로고처럼 실존 상표가 섞인 부분은 따라 그리지 말라는 설명을 붙였습니다.

회차별 결과

1화 재생성: 자동 재설계

첫 제작은 검토에서 떨어져도 사람이 다시 요청하기 전까지 멈췄습니다(1화 0/8). 소설처럼 검증 뒤 자동으로 고치도록 서버를 바꾼 뒤(vibelore PR #5) 1화 8장면을 처음부터 다시 만들었습니다.

  • 자동 재설계. 이미지 검토나 사전 검증에서 떨어지면 서버가 관측된 결함(칸 수 차이, 원문과 다른 글자·화자, 연속성)을 정리해 장면을 다시 설계하고 새 이미지를 요청합니다. 한 장면에 최대 2번까지이며, 떨어진 시도의 그림과 판정은 그대로 남깁니다.
  • 글자 규칙을 이미지 프롬프트에. 화자는 말풍선 꼬리와 위치로만 표시하고, 인용 문구 외 글자와 참조 이미지의 글자는 그리지 않도록 했습니다. 첫 제작 때 연출 지시에만 있던 규칙입니다.
  • 재시도는 긍정형으로. 재시도 지시에는 무엇이 틀렸는지 적지 않고 원하는 결과만 적습니다. 정확히 써야 할 문구를 원문 그대로 다시 인용하고, “이전 시도·틀린 결과·금지” 표현은 서버가 거절합니다. 틀린 형태를 다시 보여 주면 모델이 그쪽으로 끌리기 때문입니다. 이 규칙은 1화 제작 도중(4장면부터) 적용했습니다.

반복된 결함

  • 없는 글자 창작. 1화 3장면에서 방송명이 원작의 ‘판결 LIVE’ 대신 영어 ‘JUSTICE LIVE’로 그려졌고, 앞 장면 이미지를 다음 장면의 참조로 넘기면서 1화 끝까지 번졌습니다(2화는 ‘NIGHT COURT’). 원작과 다른 고소 내용, 썸네일 문구, 메뉴 이름 창작도 반복됐습니다.
  • 한 글자·문장부호 변형. 컸다→켰다, 윈윈→원원, 블러→불러, 붙어요→불어요, 들리지→들리치. 원문 대사의 따옴표가 빠지거나 마침표가 쉼표로 바뀐 경우가 많습니다. 검토 기준이 원문과 글자 단위 일치라 이런 차이도 ‘수정 필요’가 됩니다.
  • 재생성 뒤에도 남은 것. 1화 1장면은 세 번 모두 ‘컸다→켰다’, ‘윈윈→원원’을 틀렸습니다. 전체를 다시 그리는 방식으로는 이미지 모델의 한글 습관이 고쳐지지 않았습니다. 8장면은 세 번 모두 계획보다 한 칸을 더 그렸습니다. ‘않’ 받침이 뭉개지는 것도 여러 장면에서 되풀이됐습니다(읽기에는 지장 없음).
  • 말풍선 이름표. 1화 첫 장면은 영어 이름표(Jaeyun:), 3화 마지막 장면은 한글 이름표(채리, 재윤)가 붙었습니다.
  • 참조 인물 복제. 3화 첫 장면에서 이름 없는 스트리머들이 서아·채리의 옷차림을 그대로 가져왔습니다.
  • 잘된 점. 스릴러 톤, 방송 UI 연출, 세 인물의 식별은 24장면 내내 안정적이었습니다. 1화 6장면(99% 정지)과 3화 3장면(비어 있는 302호)이 대표적입니다.

제작 중 바꾼 연출 지시

결함을 본 뒤 이후 장면의 연출 지시(direction)에 규칙을 더했습니다. 다만 서버가 이미지 모델에 보내는 프롬프트에는 이 지시가 그대로 들어가지 않고, 사전 검증 단계가 요약한 30단어 이내 스타일 문장과 칸별 순간 설명만 들어갑니다. 그래서 규칙의 효과는 간접적이었습니다.

비용

밝혀 둘 한계

  • 작품 설계 인터뷰 답, 작품 생성 입력, 첫 이야기 뼈대는 대화 세션의 모델(Opus 5.5)이 직접 작성했습니다. 뼈대 품질 심사는 새 CLI 프로세스가 했습니다(82점 통과). 당시 서버의 심사 프롬프트에 0~100 척도가 빠져 있어 하네스가 척도 한 줄을 보충했습니다.
  • 모든 모델 호출은 도구 없는 새 CLI 프로세스로 실행했고 프롬프트 캐시는 끈 상태(DISABLE_PROMPT_CACHING=1)였습니다.
  • 이미지 모델 선택을 확정하려면 서버가 컷 단위 각색 계획 승인을 요구해, 장면 경로에서는 쓰지 않는 1화 콘티를 한 번 만들었습니다. 그 과정에서 재시도 한도 소진과 서버 버그(분할 계획 조립 시 필드 누락, 로컬 한 줄 수정)가 있었고, 비용 표의 ‘이미지 모델 확정 관문’이 그 비용입니다.
  • 1화 1장면 3번째 시도의 검토에서 계획 칸 수(7칸, 재설계 때 바뀜)를 8칸으로 착각해 ‘칸 수 일치’라고 적었습니다. 그림은 8칸이라 실제로는 불일치입니다. 판정은 어차피 수정 필요였지만, 이 페이지에는 [정정]으로 표시했습니다. 서버에 저장된 검토 기록은 제출한 그대로입니다.
  • 재생성 1화의 이미지 12장 비용은 첫 제작 때 장당 실측 평균으로 추정했습니다.
  • 장면별 이미지 비용은 OpenAI 사용량 API의 창 합계를 호출 수로 나눈 값입니다(병렬 호출이라 호출별 대응 불가).
