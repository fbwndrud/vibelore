PRODUCTION NOTES

제작 노트

어떻게 만들었고, 무엇이 틀렸는지 적었습니다. 수치는 API 실행 기록에서 읽은 값입니다. 그림 검토는 제작을 조율한 Claude Opus 5.5가 했습니다. 각색 모델과 다른 모델이지만 독립 평가는 아닙니다.

만든 순서

  1. 작품 고르기. 인기 웹툰 경향을 참고한 후보 다섯 가운데 사용자가 로판 회귀 복수극을 골랐습니다. 인터뷰에서 통쾌한 역전, 자기 과거로 회귀, 복수 중심에 로맨스 양념, 누명 쓴 악녀, 1인칭 황녀, 법·관습의 허점과 미래 지식, 쉽게 시작해 점점 복잡해지는 전개를 정했습니다.
  2. 설계. 독서 계약(StoryProfile)은 대화 세션의 Claude Opus 5.5가 인터뷰 답을 정리해 만들었습니다. 작품 생성, 이야기 뼈대(StorySpine), 작가 스킬은 GPT-6 Sol이 만들었습니다. 뼈대 심사 88점, 작가 스킬은 ‘누가 보는 앞에서’입니다.
  3. 아크. 첫 아크 안은 같은 날짜 확인이 반복돼 사용자가 거절했습니다. 연회·무도회 무대를 강화한 두 번째 안 ‘칼날 아래서 샹들리에까지’가 승인됐습니다.
  4. 소설 1~3화. lore_write 자동 모드로 화별 계획 → 초고 → 결정론 검사 → 비평 → 필요한 최소 수정 → 커밋 순서로 진행했습니다. 초고에서 날짜 정본(판결문은 아흐렛날로 잘못 적었고, 원본과 증거 목록은 열하룻날)이 흔들린 화, 1화에 ‘1분’이 빠진 문제, 3화가 아크의 비트를 건너뛴 문제가 있었습니다. 그래서 되돌린 뒤 지시를 명시해 다시 썼습니다. 1화는 되돌린 뒤 Sol이 다시 쓴 원고를 손수정 승인 흐름(lore_sync)으로 반영했습니다.
  5. 웹툰 인터뷰. 작화(한국 로판 웹툰풍), 문자(standard), 판면(세로 스크롤), 경로(장면 통합, 칸 수 auto)는 사용자가 골랐습니다. 나머지 권장안도 모두 승인했습니다. 유료 이미지 API는 ‘자동 재생성 없이 장면당 1회’ 조건으로 승인했습니다.
  6. 기준 이미지. 인물 넷과 장소 셋의 기준 이미지를 먼저 만들었고, 사용자 확인을 거쳐 해당 장면에 참조로 붙였습니다.
  7. 장면 웹툰. Sol이 화마다 원문을 9장면으로 나눴습니다. 장면마다 각색(사실·비트·대사 선택) → 사전 검증 → 이미지 API 한 번 → 실제 이미지 검토 순으로 진행했습니다. 앞 장면의 완성 이미지는 다음 장면의 참조로 넘겼습니다. 1~3화는 작업 공간을 나눠 병렬로 만들었습니다.

기준 이미지

장면 생성 때 이미지 모델에 함께 보낸 참조입니다. 에드리안의 입가 흉터가 설정(오른쪽)과 반대쪽에 그려졌지만, 사용자 확인에서 그대로 쓰기로 했습니다.

회차별 결과

‘검토 통과’는 서버 판정입니다. 서버는 그림의 칸 수가 각색 계획과 한 칸만 달라도, 글자가 원문과 한 글자만 달라도 ‘수정 필요’로 판정합니다. 칸 수만 어긋난 장면은 리더에 [서버 판정]으로 표시했습니다.

반복된 결함

  • 한 글자 오탈자. 가장 큰 결함입니다. 27장면 중 15장면에서 말풍선이나 내레이션 글자가 한 글자씩 바뀌었습니다. ‘북부’가 ‘복부’로 네 장면에서 되풀이됐고, ‘장부→창부’, 주인공 이름 ‘아델리아→아멜리아’, ‘무죄→목죄’처럼 뜻이 크게 바뀐 경우도 있습니다. ‘승인→숭인·송인’, ‘서기관→서가관’, ‘제가→재가’처럼 비슷하게 생긴 글자로 바뀌는 오류가 대부분입니다. 긴 내레이션일수록 많았습니다.
  • 칸 수 한 칸 차이. 칸 수를 auto로 두면 각색 계획이 칸 수를 정하는데, 이미지 모델이 계획과 다른 칸 수(대부분 한 칸 더)를 그린 장면이 여섯 있었습니다. 그중 1화 9장면과 3화 4장면은 글자가 모두 맞았는데도 이 차이 하나로 ‘수정 필요’가 됐습니다.
  • 원문에 없는 대사. 2화 3장면에서 군중 대사 두 줄을 지어 넣었습니다. 이후 장면에는 군중이 말없이 반응하라는 규칙을 더했고, 같은 결함은 다시 나오지 않았습니다.
  • 따옴표. 원문 대사의 따옴표를 말풍선에서 빼는 경우가 많았습니다. 웹툰 말풍선의 관례이기도 해서, 중간부터는 각색 단계에서 따옴표를 빼고 계획하도록 바꿨습니다.
  • 잘된 점. 네 인물의 얼굴과 옷, 처형장·연회장·무도회장 배경, 장면 사이 연결은 27장면 내내 안정적이었습니다. 1화 9장면(칼이 멈추는 순간)과 3화 3·4장면(첫 춤)이 대표적입니다.

제작 중 바꾼 연출 지시

1화 초반부터 · 인물 위치
1화 첫 장면에서 집행관 카르단이 귀족석에 섰습니다. 그래서 카르단은 처형대의 칼 옆에, 에드리안과 로웬은 귀족석에 두고, 아델리아의 손목은 묶인 채로 두도록 지시했습니다. 지시가 반영되기 전에 시작된 1화 4장면에서도 카르단이 귀족석에 섰습니다.
2·3화 · 장면별 장소 지시
처음에는 화 전체의 장소(처형장 → 연회장)를 한 문장으로 줬습니다. 그러자 2·3화 첫 장면의 사전 검증이 ‘원문 범위를 넘는 장소’라며 두 번 연속 막았습니다. 장면마다 그 장면의 장소만 주도록 바꾸고, 막힌 두 장면은 새 작업 공간에서 다시 시작했습니다. 이 단계에서는 이미지를 만들지 않았습니다.
제작 중반부터 · 따옴표
말풍선 대사는 원문의 따옴표 안쪽만 옮기도록 각색 규칙을 바꿨습니다.
제작 후반부터 · 군중 대사와 피
계획에 없는 말풍선을 그리지 말고 군중은 말없이 반응하게 했습니다. 칼날에도 피를 그리지 말라고 명시했습니다.

토큰과 비용

제작 중 고친 서버 버그

  • 이야기 뼈대 심사 척도. 심사 프롬프트에 0~100 척도가 빠져 있어, Sol이 1~5점으로 채점했고 뼈대가 늘 탈락했습니다. 척도를 명시하고, 5점 이하 답은 척도 오류로 거절하도록 고쳤습니다.
  • 작가 스킬 후보 조건. 검증기가 요구하는 최소 개수가 프롬프트에 없었고, 오류 메시지에도 어느 후보가 무엇을 어겼는지 나오지 않았습니다. 두 가지를 모두 채웠습니다.
  • 장면 경로의 이미지 선택. 새 작품의 장면 웹툰이 유료 이미지 API를 쓰려면 컷별 콘티를 한 번 승인해야 했습니다. 장면 도구가 직접 이미지 선택을 묻고 확정하도록 바꿨습니다(needs_image_choice). 이 작품의 1화 첫 장면이 이 흐름으로 확정됐습니다.

밝혀 둘 한계

  • 작품 발견 인터뷰와 독서 계약은 대화 세션의 Claude Opus 5.5가 정리했습니다. 이후 설계·집필·각색의 모델 응답은 모두 GPT-6 Sol이 도구 없이 단발 API 호출로 냈습니다.
  • 그림 검토는 대화 세션의 Claude Opus 5.5가 실제 이미지를 확대해 읽고 작성했습니다. 각색 모델과는 다른 모델이지만, 제작을 조율한 쪽의 검토라 독립 평가가 아닙니다. 초기 몇 장면은 확대 없이 읽었다가, 나중에 확대해 다시 확인했습니다(오탈자 추가 없음).
  • 2·3화 첫 장면은 사전 검증에서 막힌 첫 시도를 버리고 새 작업 공간에서 다시 시작했습니다. 버린 시도의 모델 호출도 비용에 포함했습니다.
  • 이미지 비용은 OpenAI 사용량 API의 시간 창 합계입니다. 같은 창에 다른 작업의 이미지 호출이 섞여 있어(46건 중 이 작품 34건), 장당 평균에 34를 곱한 추정값을 적었습니다.
  • GPT-6 Sol 호출은 토큰 수만 기록했습니다. 요금은 이 페이지에서 환산하지 않았습니다.
