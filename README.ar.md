**أداة محلية لكتابة روايات الويب بالذكاء الاصطناعي ثم تحويلها إلى ويبتون، تحافظ على تماسك عالم القصة حتى بعد مئات الفصول.**

*Write serial fiction with your AI coding agent, keep the lore consistent for hundreds of chapters, then adapt it into webtoon scenes. Local, Markdown, no extra API keys for writing.*

## إذا سلّمت رواية طويلة إلى ذكاء اصطناعي ببساطة

**❌ من دون vibelore**

- قرابة الفصل العاشر تتغير صيغ المخاطبة، وتتكلم شخصيات ماتت، وتتبدل قواعد القدرات خلسة.
- تنسى أنت والذكاء الاصطناعي التلميح الذي زُرع في الفصل الثالث.
- حين تنقطع الجلسة تبدأ من لصق «ملخص ما سبق» من جديد.
- لتحويلها إلى ويبتون تشرح في كل مرة من الصفر توزيع اللوحات وملامح الشخصيات ومواضع الحوار.

**✅ مع vibelore**

- يبقى العالم والشخصيات والنص نسخةً مرجعية بصيغة Markdown، وتُقارن مسودة كل فصل بها: **المخالفات من نوع hard تُصحَّح، والمخالفات من نوع soft تُعرض عليك.**
- يسير التخطيط بترتيب العمل كله ← القوس السردي ← الفصل، ولا يصبح قيدًا على الفصل التالي إلا ما وافقت عليه.
- يُستأنف العمل المنقطع من الموضع نفسه، ولا تُعتمد إلا المخطوطات التي اجتازت الفحص، ويمكن الرجوع فصلًا فصلًا.
- تُحدَّد لغة العمل بمعامل واحد هو `language`، وتسلك اللغات غير الكورية المسار نفسه.
- يأتي معها مسار لإنتاج الويبتون يأخذ الشخصيات والحالة من العمل الأصلي كما هي، ويحدد نطاق العمل الأصلي وأسلوب الرسم والرسوم المرجعية وعدد اللوحات ونموذج الصور، ثم يولّد كل مشهد صورةً واحدة بما فيها الحوار.

## عرض في 30 ثانية

يكفي أن تقول هذا في محادثة المضيف.

> اكتب الفصل التالي. اعرضه عليّ حين تنتهي، واعتمده حين أوافق.

```text
مقابلة العمل — مرة واحدة
  ▼
تصميم العمل — موافقة
  ▼
خطة القوس السردي — موافقة
  ▼
خطة الفصل — تلقائيًا
  ▼
المسودة
  ▼
فحص عالم القصة والخط الزمني ولغة العمل — تُصحَّح مخالفات hard
  ▼
المراجعة — advisory
  ▼
الموافقة — المستخدم
  ▼
الاعتماد — ملفات Markdown
```

تصميم العمل هو توليد العالم والشخصيات، ثم الموافقة على القصة الكاملة (StorySpine) وعلى مهارة الكاتب الخاصة بالعمل (WriterSkill)،
ولا تبدأ الكتابة إلا بعده. ويُطبَّق فحص لغة العمل على كل الأعمال، بما فيها الأعمال الكورية.

عندما تصل المخطوطة وأدلة المراجعة، أجب بـ«موافق» أو «صحّح هذا الجزء وأعد المحاولة». وضع `auto` يعتمد
تلقائيًا عندما تجتاز المسودة الفحوص الإلزامية وتكتمل المراجعة. تُسجَّل ملاحظات advisory من المراجعة ولا تمنع الاعتماد،
وإذا لم تكتمل المراجعة تعود المسودة إلى انتظار الموافقة. والويبتون أيضًا تكفيه جملة واحدة.

> حوّل الفصل الأول إلى ويبتون. اسألني عن اتجاه الإنتاج أولًا.

```text
نطاق العمل الأصلي وأسلوب الرسم والمراجع وعدد اللوحات ونموذج الصور — يختارها المستخدم
  ▼
إخراج المشهد — بالإنجليزية
  ▼
فحص ما قبل التوليد — حظر hard
  ▼
صورة المشهد مع الحوار — الحوار بنصه الأصلي بلغة العمل
  ▼
مراجعة الصورة — إعادة تصميم تلقائية عند الإخفاق
```

عدد اللوحات عدد صحيح (من 1 إلى 12) أو `auto`، والرسوم المرجعية ملفات صور للشخصيات والخلفيات يحددها المستخدم.
يُختار نموذج الصور من نماذج OpenAI API `gpt-image-2` و`gpt-image-2.5-sunburst` (الافتراضي) و`gpt-image-2.5-flare`،
والمضيف هو من يستدعيه. إذا أخفق فحص ما قبل التوليد أو مراجعة الصورة، يُعاد تصميم المشهد انطلاقًا من العيوب ثم يُولَّد من جديد
(مرتين افتراضيًا و3 مرات كحد أقصى، وكل مرة استدعاء صورة مدفوع). النتيجة صورة المشهد مع `scene.html`
تحت `.vibelore/webtoon/candidates/`.

## التثبيت

أعطِ عنوان المستودع لأداة البرمجة بالذكاء الاصطناعي التي تستخدمها (Claude Code أو Codex أو Grok CLI) واطلب منها.

> نزّل https://github.com/fbwndrud/vibelore وسجّله كخادم MCP.

كل ما تحتاجه هو Node.js بالإصدار 22.13 أو أحدث (22.x) أو 24.x أو 26.x. لا بناء ولا تثبيت للاعتماديات.
بعد انتهاء التسجيل، أعد تشغيل أداة الذكاء الاصطناعي مرة واحدة.

<details>
<summary>للتسجيل عبر npm</summary>

شغّل خادم MCP من حزمة npm [`vibelore`](https://www.npmjs.com/package/vibelore) من دون تنزيل المستودع.

```bash
claude mcp add-json vibelore '{"command":"npx","args":["-y","vibelore"]}' --scope project
```

في Codex استخدم `command = "npx"` و`args = ["-y", "vibelore"]`، وفي Grok CLI استخدم `grok mcp add vibelore -- npx -y vibelore`.
في Windows أضف `cmd /c` قبل `npx` (`"command":"cmd","args":["/c","npx","-y","vibelore"]`).
لتثبيت إصدار بعينه اكتب `vibelore@<الإصدار>`. طريقة npm تسجّل خادم MCP فقط، لذا ثبّت مهارات المقابلة
بطريقة المستودع أدناه أو بإضافة Codex.
</details>

<details>
<summary>لتنزيل المستودع وتسجيله بنفسك</summary>

```bash
git clone https://github.com/fbwndrud/vibelore.git
```

Claude Code:

```bash
claude mcp add-json vibelore '{"command":"node","args":["/absolute/path/to/vibelore/src/server.js"]}' --scope project
```

Codex (`~/.codex/config.toml`):

```toml
[mcp_servers.vibelore]
command = "node"
args = ["/absolute/path/to/vibelore/src/server.js"]
startup_timeout_sec = 30
tool_timeout_sec = 6000
```

Grok CLI:

```bash
grok mcp add vibelore -- node /absolute/path/to/vibelore/src/server.js
```

في Claude Code توجد مهارة حلقة الكتابة في `hosts/claude/skills/novel/`، ومهارتا مقابلة العمل ومقابلة الويبتون في `skills/story-discovery-interview/` و`skills/webtoon-discovery-interview/`. انسخها كلها إلى `.claude/skills/`. ويمكن أيضًا تثبيت هذا المستودع كإضافة Codex (`.codex-plugin/plugin.json`).
</details>

بعد التثبيت ابدأ عملك الأول. يكفي أن تصف القصة التي تريد كتابتها في جملة أو جملتين.

> أريد أن أبدأ رواية جديدة. إنها قصة سائق حافلة ليلية يستمع إلى ندم ركّابه. ابدأ بمقابلة العمل.

لا تسأل المقابلة إلا عن التفضيلات التي تغيّر النتيجة، من 4 إلى 5 أسئلة في كل مرة. لتخطيها قل «قرّر تلقائيًا
من دون أن تسألني». وإن تعثرت، راجع [دليل البدء](docs/GETTING_STARTED.en.md).

## ماذا تفعل

- **مقابلة العمل.** بدلًا من اسم النوع الأدبي تسأل عن الإيقاع والصعوبة والعاطفة والمكافأة والمحظورات لتبني عقد القراءة (StoryProfile)، ثم تولّد العالم والشخصيات تلقائيًا.
- **تصميم الأقواس السردية.** تحصل أولًا على موافقتك على وعد يمتد من 3 إلى 20 فصلًا مع أحداث وضغوط وتحولات مختصرة، ثم تملأ خطط الفصول تلقائيًا وقت الكتابة.
- **فحص وتصحيح في كل فصل.** تقارن المسودة بالشخصيات وصيغ المخاطبة ووجهة النظر والخط الزمني والتلميحات، وعند التعارض مع حقائق ثابتة تصحّح وتعيد الفحص تلقائيًا (3 فحوص على الأكثر، وبينها تصحيحان على الأكثر). أما ملاحظات الذوق مثل الأسلوب أو الإيقاع فتبقى advisory فقط.
- **مرجع الأسلوب.** إذا عيّنت فصلًا أعجبك مرساةً للأسلوب، تتبع الفصول اللاحقة ملمسه.
- **الرجوع.** أرجع العمل كله إلى نقطة فصل معيّن ثم اكتب من جديد بدءًا من الفصل التالي (تُحفظ الحالة السابقة للرجوع بحيث يمكن استعادتها).
- **التحويل إلى ويبتون.** تأخذ حالة العمل الأصلي، وتؤكد نطاق العمل الأصلي وأسلوب الرسم والرسوم المرجعية وعدد اللوحات ونموذج الصور، ثم تُنجز كل مشهد صورةً واحدة بما فيها الحوار.

**ما لا تفعله.** واجهة ويب رسومية (محادثة المضيف هي الواجهة)، واستدعاء واجهات API مدفوعة من خادم MCP نفسه (واجهات API للصور
يشغّلها المضيف)، وإعادة كتابة فصل سابق أو إعادة حساب الحالة اللاحقة بالأدوات الافتراضية (لا تفعل ذلك إلا أداتا الاسترداد
`lore_rewrite` و`lore_refold` في `VIBELORE_MCP_SURFACE=advanced`)، وضمان الجودة الأدبية،
والتحرير المتزامن أو تعدد المستأجرين، والتقسيم التلقائي إلى PNG/JPEG للمنصات.

## مهام شائعة

| ما تريده | قل هذا للمضيف |
|---|---|
| لا يعجبني الفصل الأخير | عدّل المخطوطة يدويًا ثم قل «تحقق من التغييرات» ← فحص ← موافقة |
| كتبت حتى الفصل 3 لكني أريد إعادة الكتابة بدءًا من الفصل 2 | «ارجع إلى نقطة الفصل 1» ← «اكتب الفصل التالي» |
| أريد إرجاع كل شيء إلى نقطة الفصل 5 | «ارجع إلى نقطة الفصل 5» |
| أسلوب هذا الفصل مناسب تمامًا، أريد الاستمرار عليه | «اعتمد الفصل 3 مرجعًا للأسلوب. السبب: الحوار قصير وجاف» |
| عدّلت ملفًّا من ملفات عالم القصة يدويًا | «تحقق من التغييرات» ← تخبرك بنطاق الأثر والخطوة التالية |
| أريد أن أرى لماذا كُتب هكذا | «أرني أدلة المراجعة وطلب الكتابة الفعلي لهذا الفصل» |
| أريد تحويل رواية موجودة إلى ويبتون | «حوّل الفصل 1 إلى ويبتون. اسألني عن اتجاه الإنتاج أولًا» |
| أريد إعادة رسم مشهد في الويبتون | «أعد رسم هذا المشهد من الفصل 1 [هكذا]» |

للتصحيح والاستئناف والنسخ الاحتياطي راجع [استكشاف الأخطاء والنسخ الاحتياطي](docs/TROUBLESHOOTING.en.md).

تُرسم الصور بنموذج صور OpenAI الذي يختاره المستخدم (`gpt-image-2` أو `gpt-image-2.5-sunburst` (الافتراضي) أو `gpt-image-2.5-flare`)، ويستدعيه المضيف عبر API. يلزم مفتاح API وفوترة منفصلان، وقبل المشهد الأول يُعرض عليك النموذج والتكلفة وما سيُرسل، ثم يُثبَّت الاختيار لكل عمل بناءً على جوابك. تُحفظ نتائج الويبتون منفصلة عن النسخة المرجعية للرواية ولا تغيّر الرواية.

## لماذا vibelore

ليست أداة تكتب الرواية نيابةً عنك من مجموعة قواعد. إنها تتفق أولًا على تجربة القراءة، وتحافظ على قدرة الذكاء الاصطناعي الإبداعية،
ولا تتحمل إلا مسؤولية الذاكرة والسببية والاتساق والموافقة والاسترداد، وهي ما ينهار بسهولة في العمل الطويل.

- **عقد القراءة أولًا.** لا اسم النوع الأدبي، بل الإيقاع والصعوبة والعاطفة والمكافأة والمحظورات، ويُحترم هذا الوعد في كل فصل.
- **السببية تتغلب على الزخرفة.** بدلًا من الإكثار من تفاصيل العالم تجعل الأفعال وردود الأفعال والنتائج مترابطة، وتبني الشخصيات بتراكم الاختيارات لا بالشرح.
- **الكلمة الأخيرة للإنسان.** مخطوطة Markdown هي النسخة المرجعية، وadvisory ليست أمرًا بالتصحيح التلقائي.

| الطرف | مسؤوليته |
|---|---|
| المستخدم | تجربة القراءة التي يريدها، والتفضيلات المهمة، والموافقة النهائية |
| الذكاء الاصطناعي المضيف | تقييم الأفكار، وبناء المشاهد، وتوليد النثر والحوار والصور، والنقد الدلالي |
| vibelore | تمرير النسخة المرجعية والخطط، وضمان الترتيب، وفحص التعارضات، وتسجيل أدلة المراجعة، والاعتماد والاسترداد |

## الأنواع المدعومة

توجد 25 قالبًا مسبقًا للأنواع، ويتتبع كل قالب عناصر مختلفة من عالم القصة (الخط الزمني، ومعرفة العودة بالزمن، وحالة العلاقات، ونظام
القدرات، وغيرها).

`صياد عائد بالزمن` `الشريرة في عالم آخر` `فانتازيا الأكاديمية` `عودة بالزمن في بيت نبيل` `انتقام المنفي` `إثارة وغموض` `أكشن`
`كوميديا` `تاريخي` `LitRPG` `LitRPG البث المباشر` `التقدم والنمو` `نهاية العالم بالنظام` `تسلق البرج` `إيسيكاي`
`الزراعة الروحية` `شيانشيا` `شوانهوان` `نواة الزنزانة` `فانتازيا رومانسية` `خيال علمي` `رعب` `حياة يومية دافئة` `حضري معاصر` `أخرى`

الأنواع غير الموجودة في القائمة والأنواع المختلطة تعمل أيضًا. تفكك المقابلة النوع إلى نبرة ونوع فرعي ومحرك قصصي لتصنع
ملف العمل، ويستخدم فحص عالم القصة أقرب قالب.

## لغة العمل

تُحدَّد اللغة التي يُكتب بها العمل بالمعامل الاختياري `language` الذي تقبله `lore_profile` و`lore_init`
و`lore_create` (أما `language` في `lore_write` فيتحقق فقط من مطابقته للغة المحفوظة). عندما يذكر المستخدم لغة الكتابة بلغة طبيعية، يحوّلها المضيف إلى وسم BCP 47
(`ja` و`pt-BR` و`zh-Hant` وغيرها) ويمرّره، وإذا لم تُختر لغة يُحذف المعامل.
الأعمال الموجودة التي لا تحمل مفتاح لغة تُعد `ko` ضمنيًا. لغة المحادثة ولغة العمل مستقلتان، فيمكنك
أن تكتب عملًا باليابانية وأنت تتحدث بالكورية.

> أريد إنشاء عمل باسم `harbor_summer` في `/absolute/path/to/my-novel`. اكتب النص بالإسبانية.

- هناك عائلتان من التعليمات. `ko` تستخدم تعليمات خاصة بالكورية، وكل اللغات الأخرى (بما فيها الإنجليزية) تستخدم عائلة تجمع
  التعليمات المشتركة بالإنجليزية مع اللغة المستهدفة. النص والعناوين والملخصات وأوصاف العالم والشخصيات والقيم الوصفية
  في الخطط والمراجعات تتبع اللغة المستهدفة، أما القيم التي تقرؤها الآلة مثل مفاتيح JSON وقيم enum والمعرّفات فلا تُترجم.
- يُقاس الطول بوحدة تناسب اللغة. الكورية تستخدم عدد الأحرف المعتاد، واللغات الأخرى تستخدم الوحدات الكتابية (grapheme)
  أو الكلمات، وأنظمة الكتابة الكثيرة الأحرف المركّبة مثل العربية والعبرية، وكذلك التايلاندية التي لا تفصل بين الكلمات بمسافات،
  تُعالج ضمن العقد نفسه.
- قبل إنشاء الـ foundation يمكن تغيير اللغة بالموافقة على revision جديدة للملف، وتمرير قيمة تختلف عن اللغة المعتمدة يُرفض بـ
  `LANGUAGE_CONTRACT_CONFLICT`. وبعد إنشاء الـ foundation لا يمكن تغييرها، وتمرير قيمة مختلفة يُرفض بـ
  `WORK_LANGUAGE_IMMUTABLE` بدلًا من الكتابة فوقها بصمت.
- يُفحص في كل فصل أن النص والملخص والخطة مكتوبة بلغة العمل، وثوابت المعنى مثل
  وجهة النظر وتسجيل الشخصيات وخلفية العالم يفحصها المدقق نفسه أيًّا كانت اللغة.
- الويبتون أيضًا يتبع لغة العمل. لا يُترجم الحوار، بل يدخل الصورة نصًّا أصليًا بلغة العمل،
  وتنص تعليمات الصورة على اللغة ونظام الكتابة واتجاه القراءة (من اليمين إلى اليسار في العربية).

جرى التحقق من كتابة الرواية ومن مسار الويبتون بالمشهد بعيّنة قبول في 8 لغات: الإنجليزية والإسبانية واليابانية والفرنسية
والكورية والعربية والصينية التقليدية والتايلاندية. وكان النموذج المضيف في هذه العيّنة Claude Sonnet 5. لتفاصيل عقد
المعاملات راجع [لغة العمل ووحدات الطول](docs/TOOLS.en.md#work-language-and-length-units).

## أين الملفات

```text
my-novel/
├── world/         خلفية العالم — يمكنك تعديلها
├── characters/    بطاقات الشخصيات — يمكنك تعديلها
├── chapters/      النص — يمكنك تعديله
├── summaries/     ملخصات الفصول
├── webtoon/       النسخ المعتمدة ونسخ SVG/HTML الرئيسية لعمل اللوحات المنفردة (deprecated)
└── .vibelore/     سجلات الفحص ولقطات الاسترداد ونتائج مشاهد الويبتون (webtoon/candidates/) — لا تلمسه
```

تبقى المخطوطات وسجلات الإنتاج على حاسوبك. وقد تُرسل المخطوطة والصور المرجعية اللازمة لطلبٍ ما إلى المضيف
وخدمة النماذج المتصلة. الحدود مذكورة في [دليل الأمان](SECURITY.md).
حقوق نشر المخطوطة لمؤلفها، ولا تنطبق عليها رخصة هذا المستودع.

## النماذج والتكلفة

- **الرواية** يكتبها النموذج الذي اخترته في جلسة المضيف كما هو. لا يوجد مفتاح API منفصل. يمكنك إعطاء تلميحات لكل مرحلة تُسند مراحل التخطيط والمسودة والمراجعة إلى نموذج أخف (في الترحيل عبر المضيف هي تلميحات فقط، ولا يتبدّل النموذج فعليًا إلا مع نموذج محلي)، أما مراحل استخراج الحقائق الثابتة فتبقى على النموذج الأساسي ما لم تحددها.
- **صور الويبتون** تأتي من واجهة OpenAI API للصور (`gpt-image-2` و`gpt-image-2.5-sunburst` (الافتراضي) و`gpt-image-2.5-flare`)، ويستدعيها المضيف، ولها مفتاحها وفوترتها الخاصة. يُحفظ النموذج المؤكد لكل عمل ولا يُغيَّر ولا يُستبدل من تلقاء نفسه.
- **نماذج النص المحلية** يمكن توصيلها بنقطة نهاية متوافقة مع OpenAI عبر متغيرات البيئة.

للإعدادات المفصلة راجع [إعدادات النماذج](docs/MODELS.en.md).

## أسئلة شائعة

<details>
<summary>هل توجد واجهة رسومية؟</summary>

لا. محادثة Claude Code أو Codex أو Grok CLI هي الواجهة، وتخرج النتائج مخطوطاتِ Markdown، وللويبتون صورة PNG/JPEG لكل مشهد (بما فيها النصوص) مع `scene.html`.
</details>

<details>
<summary>هل هناك تكلفة إضافية؟</summary>

تعمل كتابة الرواية ضمن اشتراك المضيف أو رصيده. في الإعداد الافتراضي لا تستدعي vibelore أي نموذج مباشرة (إلا إذا وصلت نموذجًا محليًا). صور الويبتون تأتي من واجهة OpenAI API للصور التي يستدعيها المضيف، وتتبع فوترة ذلك الحساب.
</details>

<details>
<summary>إذا توقف العمل في المنتصف، هل أبدأ من جديد؟</summary>

لا. سير العمل محفوظ، فتكفي كلمة «تابع» للاستئناف من الموضع نفسه. لا تُعتمد إلا المخطوطات التي اجتازت الفحص، ويمكن الرجوع باللقطات المحفوظة لكل فصل. راجع [استكشاف الأخطاء](docs/TROUBLESHOOTING.en.md#work-stopped-midway).
</details>

<details>
<summary>هل يمكنني تعديل عالم القصة أو النص يدويًا؟</summary>

نعم. `world/` و`characters/` و`chapters/` موجودة ليعدّلها البشر. بعد التعديل قل «تحقق من التغييرات» فتخبرك بنطاق الأثر والخطوة التالية.
</details>

<details>
<summary>ماذا لو كان ما التقطه المدقق في الحقيقة مفاجأة قصدتها؟</summary>

المخالفة من نوع hard تعارض مع حقائق ثابتة فتُصحَّح، لكن إن كانت مفاجأة حقًّا فغيّر ملف عالم القصة أولًا. أما المخالفة من نوع soft فقد تكون مقصودة من المؤلف، لذا لا يصححها الذكاء الاصطناعي تلقائيًا بل يسألك.
</details>

<details>
<summary>هل يمكنني الكتابة بلغات غير الكورية؟</summary>

نعم. تُحدَّد لغة الكتابة عند إنشاء العمل (في ملف العمل أو عبر `lore_create`/`lore_init`)، وتجري المقابلة باللغة التي تستخدمها. للأدلة نسخة أصلية بالكورية ونسخ إنجليزية (`*.en.md`). راجع [لغة العمل](#لغة-العمل) أعلاه.
</details>
